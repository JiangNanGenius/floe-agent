## 1. 本轮定位

Android 更接近电脑上的 Agent 工作台：Floe 负责任务、文件、授权、软件启动和成果管理；轻量文本、Markdown 和代码编辑默认直接在 App 内完成。专业编辑优先交给已安装的 Android 应用，没有合适应用时再使用项目 Linux 环境中的编辑器。

补充产品分工：有合适的 Android 原生应用时，直接跳转系统默认应用，没有默认项才显示系统选择器。用户也可以主动选择 Linux 桌面版来使用移动版缺少的专业能力，不以“未安装 Android 应用”为启用 Linux 的必要条件。Linux 同时为模型提供命令执行、工具与依赖安装、文件处理和服务运行能力；这些后台能力不要求用户先打开图形桌面。轻量编辑仍直接在 Floe 完成。

内置保留预览、手记、轻量 IDE 和简单修改，不跟随 iOS 引入专业 CAD 建模、制造/CAM、复杂多轨媒体等重型编辑器。已有功能保留恢复和迁移路径，不直接删除用户工程或已有编辑成果。CAD 继续以只读预览为边界；PDF 通用处理继续走任务 Linux 工具；系统/云语音不增加 App 本地模型；暂不增加双端实时同步。

三组能力都增强：Agent/终端/文件/技能/MCP，手机操作/定时/网络/Shizuku/ADB，以及系统/云语音与图片/视频成果；**优先完成手机操作和跨 App 任务**。

既有 G/C/IOS-D 和 183 项操作编号保留。重型编辑器按本次决定调整范围，不能把保留范围内的缺实现改名为“平台不支持”。

## 4. 必须交付的功能闭环

### 4.1 外部 Android 编辑器和文件回传

- 统一“打开/编辑”入口，轻量文本、Markdown、代码直接使用 App 内编辑器，不要求先安装软件、开启 Linux 或选择外部编辑器；用户仍可显式选择其他编辑器。专业格式优先 Android 应用，缺少合适处理程序时提供 Linux 编辑路径。
- 原始文件、任务文件和 Linux 工作文件有明确映射，使用真实 URI/文件授权，携带任务、项目、环境和修订归属。
- 根据外部应用能力使用直接授权或受控编辑副本，记录起始修订；自动检测保存结果，校验内容后回传和更新预览。
- 外部 Activity 返回、收到成功码、文件时间变化不单独算保存成功；必要时在返回前台后补查真实内容。
- 修改冲突保留两份可恢复版本，再让用户选择；应用退出、进程重启、授权撤销和旧回调不得覆盖新任务或丢原件。

### 4.2 手机控制、自动解锁与用户让路

- 复用无障碍、屏幕授权和已有 Full 深度控制通路，支持观察、点击、输入、滚动、切 App、选文件和成果确认。
- 优先界面结构，必要时使用当前配置的视觉模型；操作前检查观察仍属于当前界面、任务和设备会话。
- 普通动作按任务授权自动执行，有异常或实质歧义才弹窗。授权状态可见、可撤销；持久通知和可选悬浮按钮均有暂停/停止入口。
- 自动解锁作为独立可关闭模块，先取得用户明确同意，在手机本机配置并安全保存所需信息。解锁凭据不交给模型、不写日志、不进入备份和公开产物。
- 支持范围按实际锁屏方式、系统版本及已获权限验证。记录尝试、实际解锁、需要本人操作、失败和取消，不能把亮屏或发出请求算成解锁成功；失败后不循环尝试凭据。
- 启用后可供所有界面任务使用；只对由本任务解锁且仍由其占用的会话重新锁屏，用户接管后不强行锁屏。
- 用户正在使用手机时先暂停界面操作并弹窗，未答复不抢占；后台部分继续，空闲后按已有授权接续。
- 维持既有渠道边界：GitHub Full 提供手机深度控制、Shizuku/ADB/Root 通路；Play 排除既定 Full-only 模块。无 Root 也尽量完成普通授权可达的功能。

平台边界：[KeyguardManager](https://developer.android.com/reference/android/app/KeyguardManager) 的普通解锁请求不能直接取消未受信任状态下的安全锁屏；用户同意本身不等于新增系统权限。自动解锁的具体路径须实测后确定，不能承诺所有设备/锁屏方式都可无人介入。后台拉起应用也需按 [Android 后台 Activity 规则](https://developer.android.com/guide/components/activities/secure-bal) 处理；持久通知不等于无条件获得前台启动能力。

### 4.3 定时和跨 App 连续任务

- 固定时间、重复计划、充电和网络连接等条件触发，复用现有调度服务；表达时区和夏令时变化，不把条件成立抖动重复执行成多项任务。
- 能后台完成的先后台完成；需要界面时检查用户占用、锁屏、授权和前台启动条件，进入可恢复等待或实际接续。
- 锁屏、进程重启、升级、权限撤销后保留必要状态；避免重复提交、重复填写和重复交付。
- 三条主流程均接通：文件编辑接力；多个 App 之间读取/填写；定时启动多步操作并交付回执。阶段中间版本可明确标注尚未实测/存在故障的路径。

### 4.4 日志上报完整链路

- 自动类别仅限首次明确同意后的 App 崩溃和应用自身故障；普通任务失败、工具执行错误、模型/供应商业务错误、用户取消等**不自动上报**。
- 手动反馈可选择提交本地诊断；界面执行截图用于当前模型任务，不因此进入日志上传队列。默认不上传截图，用户手动选择的附件才附带。
- 按允许字段采集并脱敏，限制长度、数量和磁盘占用。密钥、解锁凭据、请求认证头、文档正文及完整对话不进入自动日志。
- 本地持久队列、断网缓存、网络策略、去重、有限退避、取消和退出同意后的停止行为完整；上报自身失败不能产生递归报告风暴。
- 文本允许任意网络；大附件和截图默认仅 Wi-Fi。保留已有本地导出作为独立可用入口。
- 接通已有反馈服务的接收端；若现有服务缺失则补对应端点和受限查询入口。返回真实报告编号/接收状态，App 可查看最近结果，便于按版本和报告编号定位。
- 验收包含服务端实际接收与 App 回执一致；只生成压缩包、发出请求或拿到泛化 HTTP 成功均不算完整链路。

### 4.5 项目 Linux 图形会话与软件安装

**2026-11-09执行分工补充（覆盖本轮较早的桌面优先设想）：** 模型以命令行为主要执行手段。能通过CLI完成的安装、批处理、文件转换、分析、编辑和成果校验，使用任务解析到的Linux环境及`exec.shell`；不把打开、常驻桌面或截图点选作为普通模型任务的前提。Linux桌面主要供用户手动使用专业软件。用户需要时，模型可以准备依赖、文件与启动命令并打开软件供用户接手；GUI交互不作为模型的默认工作通路。手机外部App自动化继续走既有授权的`phone.observe`／`phone.act`，保留明确用户请求的远程能力，不能拿Linux桌面替代手机或切换目标绕过授权。
