## Authorized scope

The next TestFlight omits bundled native Python and Node.js while retaining their
source/build recipes for recovery. TinyEMU/Linux becomes the main execution
backend. Existing scripts/data survive; Linux runtimes replace actual callers,
not just settings labels. Standard apt/dpkg, python -m pip/venv and node/npm keep
separate responsibilities. Shell and direct execution share the selected guest
environment. WASM remains a separately identified compatibility capability.

Implementation is delegated to OpenCode; primary owns architecture, interaction
judgment, integration and operational release verification. User requested only
focused checks and necessary light UI verification, cloud App compilation,
signing/Apple validation and expedited TestFlight. Device acceptance belongs to
the user. No production App Store or public App/Feather release is authorized.

The current adapter documents non-reentrant engine state and one global network
instance. Multiple host threads alone are not a concurrency fix. A single-vCPU
VM is not multi-core. Execution environment ownership alone is not native-code
containment. Never label an abandoned child or detached host thread stopped.

Crash evidence must come from the uploaded report API and matching build symbols;
private reports/credentials remain outside public documentation. TestFlight
availability, source checks and actual device behavior remain separate evidence.
