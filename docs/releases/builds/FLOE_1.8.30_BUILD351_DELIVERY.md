Apple 已处理此构建，返回 `VALID` 且未过期。Floe QA 已可安装，内部状态为 `IN_BETA_TESTING`。通过 App Store Connect 独立读回核对了中英文测试说明、测试组和审核记录。仅有内部测试组，外部审核记录为空。

## 旧磁盘与容量估算

用户在此前出现容量异常的换机 iPad 上确认，此次已清理干净。反馈未附清理前后的容量读数。

使用该 iPad 的原始磁盘登记和维护记录、配合测试磁盘内容回放，整理了 13 份已退役的 RISC-V 工作盘和 44 份旧增量。再次扫描的候选数为零。当前共享 ARM64 工作盘、工作区与保护用的校验文件均读回一致。重新下载替换安装镜像时，已核验的旧安装镜像会退役。

在模拟器中，五份旧安装镜像按单文件分配量相加为 5.55 GB。对其共享的 APFS 磁盘区段去重后，实际覆盖 2.22 GB。该组文件之外的活动 ARM64 工作盘覆盖 4.02 GB。空间概览在系统只允许测量部分区段时会标注估算范围。

## 共享 Linux 与 GPU

在真实 ARM64 Linux 客机中，缓存清理脚本使用独立挂载的工作区验证了系统盘容量读回、跳过占用中的缓存、清理可再生成的缓存以及保护数据读回。[本轮变化](../notes/RELEASE_NOTES_1.8.30_BUILD_351.md)

在 iPad 模拟器中启动了此构建使用的可下载 Linux 镜像。客机使用 Venus 驱动向 GPU 提交三组 Vulkan 计算，分别读回 3、257 和 1,048,583 个元素，逐项与 CPU 结果比对，最大误差为零。强制让图形设备初始化失败后，测试中的同一虚拟机继续用 CPU 执行指令。

同一镜像在 M5 Pro 上运行齿轮程序，取回 24 帧，其中有 20 个不同画面。iPad 模拟器的窗口测试在读取 VNC 画面时超时，MoltenVK 同时报告一项动态顶点步幅能力缺失。该次模拟器测试只确认客机 GPU 计算。M4 iPad 上的窗口渲染仍待实测。
