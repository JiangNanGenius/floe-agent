# 存储统计、清理与诊断报告

[English](FLOE_STORAGE_DIAGNOSTICS.md) · [使用手册](USER_GUIDE.zh-CN.md) · [当前版本](CURRENT_STATUS.md)

本页说明怎样查看 Floe 自己的数据、腾出空间，以及提交有用的故障材料。界面与可用操作随安装版本变化，较新工作台见[专用教程](WORKSPACES_GUIDE.zh-CN.md)。

## 先看哪些数字

打开 **设置 → 数据管理**，等待当前扫描结束或停止不需要的扫描。先区分 App 本体、用户数据、共享文件及界面列出的可清理内容，再查看较大的项目。首次扫描未结束时，不把局部结果当作最终总量。

- **逻辑大小**表示文件内容的表面长度；稀疏磁盘、压缩或克隆副本可能与实际占用不同。
- **分配空间**描述文件系统分配的空间，也不一定等于删除后能腾出的空间。共享块和系统快照会影响结果。
- **共享文件**应单独检查来源与用途，不因为名称像缓存就删除。
- iOS **设置 → 通用 → iPhone／iPad 储存空间**是系统统计口径。Floe 的数字不能当作整台设备的剩余空间，也不会替代系统统计。

## 按这个顺序清理

1. 先导出重要文档与工程，确认副本能够打开。画布、Office、3D、音乐、打印等项目要保留可编辑源文件。
2. 查看 App 提供的缓存或下载管理操作，阅读删除说明，再清理不再需要的内容。
3. 删除任务、环境或工程前，确认没有运行中的作业，也不再需要其中的文件。手记是独立资料库，不依赖某条聊天记录；删除前仍应看清当前选中的对象。
4. 清理模型或环境镜像后，相关能力可能需要重新下载。确认联网条件和后续用途，再决定是否删除。
5. 清理完成后重新扫描。可清理估计值和实际释放空间可能不同，最终核对系统可用空间。

不要在仍有运行或保存进行中时，直接到文件管理器里删除内部数据库、环境目录或工程包内容。需要移动作品时，优先通过 App 的导出、分享或文件管理入口处理。

## 文件看起来重复时

名称相同不代表内容相同。不同版本、分支、导出文件和源工程可能都有用途。反过来，克隆或硬链接也可能显示为多份文件，却共享部分存储；只靠逐个相加会高估占用。

先打开并确认内容、保存位置和可编辑性，再删除明确不需要的副本。完整工程与导出的 PNG／PDF／网格不能互相替代。

## 报告故障的主要入口

功能请求与故障报告请优先到 [GitHub Issues](https://github.com/JiangNanGenius/floe-agent/issues)。描述目标、复现步骤、预期与实际结果，附上 **设置 → 诊断与关于**中的版本及构建号。重要问题应在 Issue 中记录，便于后续讨论。

App 内诊断上传只用于补充故障材料，不是客服工单；提交不保证被查看、回复或在特定时间处理。上传前检查日志与截图，移除密码、API key、令牌及不需要提供的私人内容。

上传接口会检查客户端版本；被提示版本过旧时，按提示更新后再试。若当前 App Store 已显示最新版本但仍无法上传，可直接在 GitHub Issue 说明安装渠道和版本，不要反复提交同一材料。

## 截图与数据分享

只选择能说明问题的截图。检查画面中的文件名、账号、聊天和通知。分享作品时，确认导出格式是否保留原件中的附加资料。

诊断数据、App 本地工程与官网收到的报告分别管理。删除本地文件不等于已经删除官网提交的报告；保存或备份也不表示模型推理、云端服务与设备行为都已验证。
