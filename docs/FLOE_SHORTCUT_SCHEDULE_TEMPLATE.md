# Scheduled-task Shortcut template

`FloeAgent/FloeApp/Resources/Shortcuts/FloeScheduledTask.shortcut` is an Apple-signed template containing one `RunScheduledTaskIntent` action. Its required schedule entity starts unset and the template carries no import questions: the recipient confirms the add, then chooses the plan once in the system editor; the saved entity carries the plan's stable ID. No title-based execution fallback, real plan, task prompt or account data is embedded.

The adjacent `FloeScheduledTask.source.plist` is the unsigned source. Only the signed file is bundled, explicitly through `project.yml`. To update it, author the action in system Shortcuts with the Schedule parameter left unset and no import questions (the importer's question-completion path could not commit; see Acceptance boundary), and sign the source with Apple's `shortcuts sign --mode anyone --input <absolute-input> --output <absolute-output>`. Use task-owned internal build-cache paths for signing, then copy the verified result into the resource directory. The signing operation validates sharing with Apple; it does not prove the recipient's plan binding or execution.

Floe hands the file to the system, with a share-sheet fallback. System confirmation remains required. An opened page or completed share is recorded as a possible setup, never as a detected installation. Creating a time automation is a separate step. When a monitored plan is deleted or a one-shot run terminates, a durable reminder asks the user to remove its Shortcut and automation. Pausing a plan and finishing one occurrence of a recurring plan do not retire the plan. The user's removal or dismissal marks record their own choice; Floe does not claim it can inspect or delete system Shortcuts.

The source preserves the system-authored required-entity route. A stale trigger cannot select a newly created plan with the same title, skip the due check, or bypass occurrence claims and permissions.

Apple references: [sharing signed Shortcut files](https://support.apple.com/guide/shortcuts/share-shortcuts-apdf01f8c054/ios), [import questions](https://support.apple.com/guide/shortcuts/add-import-questions-to-shared-shortcuts-apdf330fd3a0/ios), [supported URL routes](https://support.apple.com/guide/shortcuts/open-create-and-run-a-shortcut-apda283236d7/ios), and [deleting Shortcuts in the system app](https://support.apple.com/guide/shortcuts/delete-shortcuts-apd096cd65c6/ios).

## Acceptance boundary

An earlier candidate lost its configuration question because an incorrectly renamed field was ignored. A subsequent candidate displayed the question but its Add action did not complete in the tested environment. Both failures are retained; neither candidate is bundled. Successful signing alone does not prove adding, selected-entity persistence, terminal cleanup or stale-trigger behavior. Physical-device background timing is separately qualified.

2026-10-22: the question-bearing signed template rendered its bilingual plan question and accepted a plan selection, but the native Add never completed (no record created, no error) — with `ParameterKey`-only and `Key`+`ParameterKey` archives alike, while Skip Setup committed the same selection and read-only row extraction proved the plan UUID persisted. The bundled template therefore carries zero import questions, and the required plan binding is made once in the system editor, whose selection and persistence are separately proved.

The adopted zero-question template was added through the native Add action, then bound to a plan in the system editor. Read-only inspection confirmed the exact selected plan ID persisted with one Run Scheduled Task action and no time trigger. The generic bundled file itself still contains no selected plan. Full-App handoff and cleanup monitoring were observed separately; creating and enabling the system time automation remains a user step.
