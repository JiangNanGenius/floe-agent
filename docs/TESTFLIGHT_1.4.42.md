# Floe Agent 1.4.42（Build 73）TestFlight 测试说明

本版扩展远程设备连接管理，并保持守护程序只服务于明确启用的远端执行环境。请优先验证真实设备和协议，不需要重跑已通过的全工具巡检。

## 测试重点

- **同一设备多连接：**在“主机与远程会话”中为一台设备同时保存 SSH、普通 VNC、SSH 隧道 VNC、Telnet、TCP 或 BLE 串口。关闭再进入后，连接列表和名称应完整保留。
- **设备类型可选：**新建设备保持“未指定”可以正常保存。类型只作为显示备注，不应阻止任何已配置协议。
- **普通 VNC：**普通 VNC 应直接连接所填地址；SSH 隧道 VNC 才应先建立 SSH 转发。两种连接不能相互覆盖凭据。
- **执行环境边界：**打开“作为远端执行环境”后，守护程序支持的任务应先检查版本并按需安装或更新。关闭后仍可直接使用 SSH/Telnet/TCP/VNC 管理设备，但不应安装守护程序，也不应出现在默认远端执行目标中。
- **临时连接：**在对话中提供测试地址与端口后，模型可建立不保存的 Telnet/TCP 会话；提供 BLE 外设、服务和特征 UUID 后可建立临时 BLE 串口。新任务不能复用旧 session ID，遗留连接最长 30 分钟自动关闭。
- **模型编辑：**让模型先列出设备，再修改连接名称、非秘密地址/端口或执行环境开关。模型不应索要或回显密码、密钥。
- **关于入口：**“诊断与关于”的版本区域应显示“在 GitHub 查看项目”，点击后打开项目主页。

## 反馈信息

请注明 Build 73、设备型号、iOS/iPadOS 版本、目标协议、是否启用远端执行环境、准确步骤、结果和时间。VNC、Telnet、TCP 和 BLE 的真实连通性必须由对应设备验证；Mac 编译和模拟器无法代替网络设备、蓝牙权限、钥匙串和真机后台行为。
