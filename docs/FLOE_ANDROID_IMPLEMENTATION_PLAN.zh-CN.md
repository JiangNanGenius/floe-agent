# Floe 安卓完整功能对齐与轻量化实施计划

制定：2026-10-18；本次盘点更新：2026-10-22。状态：G01与G02代码阶段及代表性接线已收口，Alpha7已公开预发布，下一活动目标为G03；G12/G13/G14的完整联调、设备与视觉验收仍未开始。

当前操作基线为`g02.2026-10-21.2`：36个功能族、183项操作，其中G02归属41项；85个工作包、33份合成样例。增量依次为G01的170项、附件补齐至172项、Settings基线`g02.2026-10-19.1`补齐至182项（其中G02为40项），以及手动上下文压缩追加至183项。历史记录保留当时计数。范围台账中的`planned`不等同于尚无代码，也不等同于操作已验收；当前实现、编译、设备行为与发行状态以[本次盘点](#g02-current-plan)和[实施记录](FLOE_ANDROID_PROGRESS.zh-CN.md)分别说明。

目标是交付能够完成当前 Floe 主要工作流的安卓产品，保留云端 Agent、手记、项目、文件、Office、终端、开发、浏览器、画布、媒体、工程图纸、远程连接与自动任务。安卓不提供本地大语言模型；允许采用系统能力、外部编辑器和按需组件降低基础安装包与运行开销。功能对齐以实际输入、操作、成果、保存和恢复为准；App内界面从开始实现就尽量复现当前iOS的整体视觉、组件与布局，底层引擎可以不同。

推荐架构为共享 Swift 业务核心、Kotlin 与 Compose 安卓应用、独立的 ARM64 Linux 执行后端。IDE 必须内置；Office 主路线采用安卓原生 LibreOfficeKit/Collabora 内核，提供 Floe 内离线预览，并逐步接入 AI 操作、计算、保存和人工编辑。外部编辑器与远程处理仅为补充；本地预览不依赖 Linux 环境、外部应用或云端服务。

## 1 范围与功能基线

### 1.1 已明确的产品边界

- 安卓不做本地大语言模型，不引入 MLX、llama 推理、模型下载及相关界面。
- 完整 APK 新增基于 AccessibilityService 的手机操作能力，任务授权、可见状态、随时停止和操作核对必须完整接入。Google Play 版在构建时移除手机操作和Root增强模块、服务声明、权限、工具注册和相关入口，不仅隐藏 UI；该渠道差异已由用户明确指定。普通网络分析和已获准的文件能力保留。
- 安卓画中画不作为后台保活手段；辅助功能服务也不作为通用保活手段。后台执行使用适用前台服务、系统调度及可恢复作业。
- 云端模型继续由用户配置；文件上传到新服务前说明对象、用途和目标，沿用任务授权。
- 至少对齐当前功能的用户结果。不同实现、按需安装和外部应用均可接受；缺少实现的功能记为缺口，不能用入口或跳转冒充完成。
- App内美术、风格、信息架构、布局、控件与状态尽量对齐当前iOS；不另做Material风格产品。系统原生权限/返回/通知/窗口等按安卓能力适配，视觉一致与最新原生特性同时落实。
- IDE 必须内置，文件树、代码编辑、Git、终端、运行、日志和预览构成同一工作台。
- Office 必须在 Floe 内本地离线预览 DOCX/XLSX/PPTX；优先嵌入安卓原生 LibreOfficeKit/Collabora 内核。人工编辑逐步完善，外部 Office 应用只是可选补充。AI 创建、修改、核验、成果回到任务的链路仍属于产品范围。
- 网络工作台为安卓重点能力，Wi-Fi分析、局域网发现、协议诊断、测速/持续监测和结构化Agent工具均内置，核心无Root可用。
- GitHub完整APK提供默认关闭的Root增强开关，仅对已有Root且用户授权的设备启用；不自动Root/解锁设备。Play构建排除Root模块，与手机操作模块分别核验。
- 无Root也是完整文件工作台：保存目录授权并复用，支持用户授权范围内完整文件操作、外部存储和网络文件；不把用户反复选文件作为默认流程。
- 新系统原生特性优先，老系统保持明确回退；三星Android13是兼容测试设备，不作为产品能力上限。采用当前稳定SDK和适用Jetpack，逐功能判断系统/API扩展/组件/硬件/权限能力。
- 优先使用现有三星 ARM64 真机测试，安卓平板采用最新稳定系统的本地 ARM64 模拟器作为新特性主验证环境，不把购买/借用平板列为启动或公测前提。
- 已实现且基本验证可用的功能向用户正常开放，不因缺少特定平板/触控笔真机而隐藏或长期锁在开发菜单；真实体验通过自愿用户反馈补齐。实际不可用、缺配置或硬件不支持时给出可操作状态；Play移除手机操作模块的例外保持。
- 保留 iOS 当前架构和发布路径；不为安卓顺便重写 iOS 界面、替换生产存储或调整现有提交。
- 本计划不创建定时跟进，不安装第三方应用，不修改设备权限，也不代表发布、购买服务或新增账户访问授权。

### 1.2 基线冻结方法

规划参考源码提交 `037698e96e6890b0b3ac6d95037e3792aa32c692`、当前使用手册和相关模块。该提交标题为 1.7.35（276）候选准备，不据此认定已交付；工作区手册另有未提交修改。

实施第一步冻结功能台账，每项记录：用户入口、真实服务路径、输入格式、支持操作、输出格式、现有资格证据、已知缺口、安卓实现、验收用例。源码存在、手册描述、组件编译、完整应用验证和物理设备结果分别记录。现有尚未验收的能力可以进入安卓目标，但不能作为已通过的参考结果。

临时会话、权限和其他存在文档差异的能力，以实施时有效的仓库约束和用户最新要求确定共同契约；先解决差异，不默默采用更宽权限。

计划冻结后继续跟进 iOS 新功能，通过台账标记加入版本、影响模块和安卓状态，避免对齐目标无限漂移。

### 1.3 对齐分级

| 标记 | 含义 | 是否满足对齐 |
| --- | --- | --- |
| 内置等效 | 安卓内置完成相同结果 | 对应测试通过后满足 |
| 系统等效 | 由安卓正式系统 API 完成 | 对应设备上通过后满足 |
| 外部协作 | 经实际验证的应用编辑并回传 | 只满足已验收的人工工作流 |
| 按需等效 | 安装可选组件后完成 | 组件与完整工作流通过后满足，明确依赖 |
| 远程等效 | 用户配置服务或主机后完成 | 满足相应远程工作流，不能宣称离线对齐 |
| 平台替代 | Apple 专属功能改用安卓方案 | 根据用户结果验收 |
| 待补齐 | 尚无可验证实现 | 不满足 |

核心内测版是阶段成果；完整对齐版必须关闭功能台账中所有必需缺口，或明确列出经用户接受的平台差异。不能把后续阶段直接从总范围中删除。

## 3 共享架构与同步更新

### 3.1 代码布局建议

保留现有 `FloeAgent/`。新增安卓应用和共享集成目录时使用仓库内明确边界，例如 `Android/` 与 `Shared/Contracts/`；最终目录在 P0 决定，不先移动现有源码。第一轮通过依赖现有 Swift 模块证明复用，再逐步拆分平台接口。

Swift 共享层优先包含 FloeModels、FloeProviders、FloeTools、FloeAgentRuntime，以及可移植的持久化、环境、文档命令和工作台数据逻辑。FloeCore 中的系统探测、存储计量、Keychain、CloudKit 和应用装配改为平台服务注入。现有 Package 声明、二进制目标与传递依赖均需审查；不要为了构建安卓让整包解析 iOS 专用大组件。

Android宿主负责权限、通知、分享、生命周期和原生编辑器集成；导航、聊天和文件等App内界面先在G01完成复用选型及代表页面验证，再固定组件边界。优先对照SkipUI源码复用与Compose Cupertino组件复用，按当前iPad实图与源码选择，不能仅因项目使用SwiftUI语法就认定外观相同。Compose路线通过Floe自有组件封装统一样式，不直接采用Material默认外观作为最终设计。Linux 服务负责实际命令和服务，不由 View 或 Activity 的存活决定。

### 3.2 内置 IDE 的交付边界

IDE 是 Floe 内部工作台，不要求另装代码编辑器。优先验证 Sora 原生编辑器，并与现有 CodeBlitz/Monaco、CodeMirror Web 宿主作小范围比较（第 16 节）；文件树、任务上下文、标签、Git、终端和运行面板归 Floe 管理，离线打开和编辑不依赖网站。

必需能力包括多文件/多标签、语法高亮、查找替换、撤销/重做、编码与换行、未保存提示、修订冲突、diff、Git 操作、运行/停止、完整日志、环境选择、服务端口与网页预览。手机采用切页和全屏编辑，平板采用可调整面板；切换布局保留草稿、选择与会话。

语言服务与智能补全按语言能力台账推进，可在已选 Linux 环境启动 LSP；不以语法高亮冒充语义补全。调试器和断点不因“内置 IDE”自动视为已有功能，按当前真实基线列出需对齐项和后续增强。源码执行继续通过统一 exec.shell 与 jobs 生命周期，不增加绕过环境的语言专属执行器。

### 3.3 跨语言边界

采用少量稳定服务接口：创建/继续/停止任务、订阅事件、审批回执、读取历史、文档操作、能力查询。事件携带任务、运行、环境、作业、修订和序列信息；大的二进制内容使用受控文件或流，不塞入 JSON。

Swift actor、数据库连接和内部泛型不直接暴露给界面。桥接优先验证 Skip Fuse 的库模式或受控 JNI/C 接口，再按生命周期、取消、性能与维护结果选择。不能让 Kotlin 与 Swift 各自维护一套任务真相。

Provider 的网络栈先验证 Swift FoundationNetworking；若实际兼容性不足，再通过统一传输接口使用安卓网络实现。不要一开始同时维护两套 Provider 请求业务。

### 3.4 技术选择门槛

| 决策 | 优先方案 | 放行条件 | 失败后的处理 |
| --- | --- | --- | --- |
| 业务核心 | 原生 Swift Android | Provider、Runtime、数据库及取消在真机跑通 | 按模块修补或抽象；重新估算，不直接全量翻译 Kotlin |
| 主界面 | G01对照现成iOS风格组件与SwiftUI复用；以Floe组件层隔离依赖 | 当前iPad参考与Android代表页面的大布局、密度、排版和组件方向通过，手机/平板及输入恢复可行 | 不通过就先修正组件和结构，不向后铺开错误页面 |
| Skip UI | 对实际Floe纯SwiftUI子树评估源码复用 | 可编译范围与UIKit/系统材质缺口有证据；Android外观对照达标，不能以默认Material3冒充iOS | 不采用整App转换；保留经验证有价值的子树或桥接工具 |
| Cupertino组件 | 优先验证Compose Cupertino维护分支，显式使用Cupertino样式 | 真实依赖解析/编译和渲染通过；覆盖Floe所需控件，可局部补齐新版材质与多栏布局 | 使用Floe封装内的定向适配/源码复用，避免业务页面绑定上游API后全面替换 |
| 数据库 | 当前 GRDB 与受控 SQLite | 事务、迁移、WAL/快照所需能力真实可用 | 先抽仓储接口，保留语义与测试，单独估算替换 |
| Linux | PRoot ARM64 | 无 root、APK 安装后真实执行、停止、文件和安全边界达标 | 修复后端或启用明确标注的远程实现 |
| Office 内核 | Android 原生 LibreOfficeKit/Collabora | 离线首帧、分页/工作表、命令、保存重开、公式与导出通过 | 先修复本地实现；外部/远程不能替代本地预览 |

### 3.5 持续更新机制

- 核心逻辑一次实现，双端运行共同测试；功能发现依据实际安装和配置。
- 给工具协议、事件、数据库、文档包、Linux 镜像、可选组件分别版本化。App 更新不自动升级并破坏用户环境。
- 新功能先定义操作与兼容范围，再接双端 UI；每次合入标注 Android/iOS/共用影响。
- 冻结当前对齐版台账；后续 iOS 变化进入差异队列，不无限阻塞既定版本。
- 设置可用能力矩阵，记录本机、可选本地、远程、只读和不可用；工具调用不得静默切换有隐私或费用变化的后端。
- 共用的资源、Skills 和目录数据可同批更新；原生代码和动态模块仍走适用的签名分发路径，不用远程脚本伪装应用升级。

## 4 Linux 与终端专项

### 4.1 默认执行架构

基础 App 内含环境管理与执行协议。用户首次需要代码执行时准备版本固定、校验通过的 ARM64 用户空间；先比较 Debian 与 Alpine，优先验证 Debian 对现有 apt/dpkg 和常见 Python 依赖的适配。

CPU 密集型工作预期受益于原生 ARM64 指令执行，但包安装、进程启动和大量小文件访问仍受 PRoot 开销影响。性能结论来自实测，不预设倍率。

Android 原生编译工具用于高频、稳定的操作；常规 Linux 包运行在明确选定的 Linux 环境。不能将 Android Bionic 可执行文件与 glibc/musl 软件包混装并宣称兼容。

### 4.2 必须重建的环境语义

现有 iOS 环境使用虚拟机，PRoot 使用宿主内核和进程，不能直接套用每个虚拟机独立 localhost、vCPU 或固定 guest RAM 的含义。

- `environmentID`、项目与任务所有权贯穿终端、包安装、子代理、作业和服务。
- 一个环境复用其受控 rootfs 和已安装状态；多个会话共享文件，但保留独立 PID/句柄、输出、退出码和取消。
- 环境目录共享、继承与写层的产品语义保留；实现采用已验证的目录/复制/模板方案，不假定普通 APK 能挂载 overlayfs。
- 原生端口使用全局分配和登记，界面展示实际端口；逻辑命名空间不能冒充内核网络隔离。
- 并发和内存采用可测的调度预算；没有内核硬限制时，不展示为已强制实施的 CPU/RAM 配额。
- 停止环境先终止其全部会话和服务，等待确认后释放引用；删除先核对活动依赖并保留恢复资产。
- 不跨 CPU 架构复制 RISC-V 的已安装二进制；迁移项目文件、依赖清单和环境说明后在 ARM64 重建。

### 4.3 执行边界

PRoot 不是安全沙箱。同 UID 的独立进程也不构成应用私有数据的强隔离。P1 必须验证可执行内容是否能访问凭据、数据库、其他项目和非授权资源。

候选措施包括独立执行身份、能力受限的文件与网络代理、受控授权目录及凭据服务；安卓 isolated process 的网络、存储和子进程限制也必须同时验证，不能仅凭声明采用。若本地方案不能达到产品要求，按实际威胁边界收缩可用权限，或为相应任务使用明确配置的远程隔离执行。此决策在大量 UI 开发前完成。

不把 root、解锁 bootloader、Shizuku 或系统虚拟机权限作为普通用户基本使用前提。辅助功能仅是用户选择启用手机操作时的专项授权，不成为聊天、IDE、Office 或 Linux 的使用前提。

### 4.4 运行与恢复

PTY、窗口大小、中文输入、外接键盘、Ctrl-C、EOF、stdout/stderr、退出码、信号、超时、输出背压、子进程树和服务管理逐项验收。使用当前任务的原始退出与结果记录，不能靠查找进程名判断任务是否完成。

重启应用后，已停止进程不再显示运行；无法确定结果的外部操作先核对再重试。杀进程后的普通 Python 内存态不承诺恢复。长任务通过阶段文件、检查点和幂等操作恢复。

## 5 内置 Office 原生内核方案

### 5.1 主路线与原生含义

采用面向 Android 编译的 LibreOfficeKit（LOK）与 JNI 适配，或采用兼容的 Collabora 安卓集成。内核运行在 Android 原生环境，不通过 PRoot 启动桌面 LibreOffice，不需要远程 Office 服务器。嵌入内核和 Floe 文档视图，而不是嵌入另一个 App 的 Activity。

LibreOffice 安卓源码提供原生共享库、JNI 引导、分块渲染与编辑事件实现；LOK 提供文档加载、渲染、工作表/幻灯片切换、命令和保存等接口。存在原生实现不等于有即插即用且覆盖 Floe 所有操作的成品 SDK，具体可用性必须在固定版本上验证。

优先对照当前 iOS 所用 Collabora 源码系列与上游 Android 路径，冻结同源版本、补丁和依赖，减少文档语义差异。现有 iOS 的 Objective-C++ 宿主和 WKWebView 桥不能原样复用；文档命令、操作白名单、修订校验、输出验证与测试样例优先共享。

### 5.2 内置预览最低要求

DOCX、XLSX、PPTX 必须在 Floe 内离线打开并显示真实内容，不以缩略图、纯文字提取、外部跳转或云端转换替代。

- Word：分页、缩放、滚动、中文字体、表格、图片、页眉页脚与关键分页样例。
- Excel：工作表切换、滚动、缩放、单元格、合并、数字格式与图表；不能仅显示第一张表。
- PowerPoint：幻灯片切换、文字图片图表和版式；动画与放映列为独立能力。
- 密码、只读、格式损坏、大文件与不支持对象有明确状态，保留原文件。
- 首个真实文档画面、引擎加载成功和文档读完分别观测，不能显示空白却报告已就绪。

原生代码与最小字体/过滤器资源优先随安装提供，确保初次安装即可离线预览。若体积实测不可接受，再评估通过正式签名渠道提供 Office 组件；组件安装后离线预览仍属硬要求。分发方案及“首次离线可用”的变化需明确决定，不能静默退化。

### 5.3 文档服务与 AI 操作

建立 Android OfficeDocumentService，统一持有文档会话、修订、命令队列和保存。Compose 视图订阅状态并承载渲染；AI 工具和人工操作经相同的可验证服务执行。同一会话不允许 UI 与 AI 无协调并发修改。

接口至少包括 open、queryCapabilities、render、selectPart、dispatchCommand、saveWorkingCopy、export、close。工具只提交 Floe 定义的命令和结构化参数，不直接获得任意 UNO、JavaScript 或宏执行能力。宏与外部链接默认不因预览而自动执行或更新，实际策略在固定内核上核验。

对于 LOK 的 tiled rendering、编辑和部分查询接口，注意其编译开关、扩展结构与不稳定 API 边界；固定头文件、内核与 JNI 为一组产物，检查版本/能力，不将 master 接口直接套到已锁定的旧二进制。

原生 LOK 视图和 Collabora 本地 Web 编辑界面作为 P1 对照：前者视图简单但要自行完成输入、选择与工具栏，后者可能复用更多现有命令/UI但集成面更大。两者均为本地引擎；不能将“Web 界面”误当作必须联网。根据真实可用操作、包体、输入法和维护成本选择主实现，避免同时维护两套渲染引擎。

### 5.4 线程 生命周期与恢复

LOK 调用通过固定的串行引擎执行通道，遵循所选版本的线程要求；绘制与界面更新分离，限制 tile 缓存、回调队列与单次输出。不能在 Compose UI 线程同步打开、重算或导出大文件。

优先评估专用 Office 服务进程，减少引擎崩溃对整个 App 的影响；同 UID 进程不构成安全沙箱，也不据此宣称引擎能热重启。重启前确认旧进程、线程、句柄和文档会话已退出，跨进程 tile 传输和缓存需测内存与吞吐。文档恢复使用已落盘的工作副本，不保留失效原生指针。

文件通过受控工作副本进入引擎，记录原始修订。显式保存需要本次请求的完成证据，不能由自动保存事件代替。成功后校验文件结构、语义和实际重开，再按来源能力提交；并发修改保留两份，磁盘不足或进程死亡保留恢复副本。

### 5.5 公式 排版 导出与人工编辑

采用内核真实计算和渲染，验证 Excel 公式缓存值、类型和错误，检查 Word/PPT 页布局及 PDF 输出。写入公式、设置重算标志、收到命令完成或产生非空文件都不能单独作为成果正确的证据。

操作级覆盖当前段落、表格、单元格、样式、幻灯片、图片、批注、修订、图表、附件、笔迹与导出要求。需要现有 Collabora 补丁的功能逐项移植并验收；上游具有 UNO 命令不等于特定安卓内核已暴露、已启用或可安全调用。

人工编辑先支持基本选择、输入、撤销、保存，再扩展格式、批注和修订。外部应用仍可选择，使用最小 URI 授权及可恢复编辑副本，回到 Floe 后重新读取并验证。外部编辑不作为内置预览或必需 AI 操作的替代验收。

### 5.6 体积与维护

先确保固定版本的正确打开、显示、修改、保存与重开，再裁剪。原生 ARM64 不意味着包体小：内核、格式过滤器、字体、语言资源、图片与图表服务都会贡献体积。先裁剪无用 ABI、调试符号和不必要语言/桌面资源，再测可移除服务；不能去掉 Calc/Impress 或字体后仍宣称完整对齐。

每组产物保留源码版本、补丁、构建参数、NDK、依赖、资源摘要、符号和许可证/对应源码义务清单。验证 4 KB 和 16 KB 页、C++ 运行库、现代安卓加载行为、资源路径和中文字体。编译通过与三星能显示文档分别验收。

P1 依次完成三类样例的离线打开与显示，再完成 AI 修改、Excel 重算、保存重开与 PDF 导出；记录冷/热打开、压缩/安装体积、PSS、CPU与退出后残留。未通过时先解决本地路径，不以外部打开宣布 Office 完成。

## 6 文件 手记 PDF 与数据

### 6.1 文件的四种来源

区分应用私有项目、用户授权的 SAF 文档、网络/云端文件和只读导入副本。URI 不等于 POSIX 路径，Linux 工具不能直接访问任意 `content://`。使用受控暂存、文件代理或明确同步工作副本；每次回写都校验授权和来源修订。

不要求所有文件管理权限作为基础功能条件，但为确需广泛共享存储管理的用户提供适用的所有文件访问路径；SAF长期目录授权与其并存，详见第21节。权限撤销、源文件移动、提供方离线、不支持原子替换和磁盘不足时保留草稿与恢复副本。远程文档 Provider 不承诺本地文件系统的重命名和锁语义。

应用私有目录可采用本地原子提交；SAF/网络目标使用提供方能力允许的事务或分阶段保存，不能把后者标为已实现原子覆盖。

### 6.2 手记与笔迹

手记继续是独立工作区，保留资料库、搜索、封面、阅读模式、助手、独立对话、选择、撤销、页面和附件。删除聊天不删除手记。

安卓用指针与触控笔输入实现笔迹，手机手指操作与平板笔输入分别设计。跨端笔迹建立可移植格式，记录点、压力、颜色、宽度和变换；若 iOS 历史文件包含 PencilKit 专属数据，导入时保留原始数据与可显示预览，完成转换验证前不承诺可编辑。

`.floenote`、`.floecad`、画布与媒体包统一校验清单、版本和附件摘要。新格式不能被旧端无损理解时，拒绝破坏性回写或另存兼容副本。

### 6.3 PDF 与 OCR

三星 Android 13 上先验证系统 PDF 渲染。文本提取、搜索、选区和编辑不能依赖仅在较新 API 才出现的能力，需要兼容库或其他已验证后端。

2026-10-18 核对的 AndroidX PDF 已有 1.0.0-beta01；官方记录部分读取/渲染能力回移到 minSdk 28。不能再笼统排除这台 Android 13 三星，但编辑/OCR/选择等特性仍按库版本和 SDK Extension 实测，不能据此宣布全部回移。

PDF 批注与手记叠加保持可撤销、页坐标正确和导出可见；保留原始 PDF。受保护 PDF 沿用保护检查和授权边界。扫描件使用系统/按需 OCR 或用户配置服务，上传前遵循授权。

### 6.4 备份与同步

先做用户显式导出/导入和跨端文档包交换，再实施跨平台同步。迁移采用包级版本和数据校验，不直接复制正在使用的 SQLite 数据库或平台 Keychain 内容。

跨端实时同步单独设计传输、认证、冲突、删除墓碑、资产引用和兼容版本。现有 iCloud 可继续服务 Apple 平台；安卓不能通过一个开关就继承现有 CloudKit/Keychain 行为。传输候选包括用户控制的服务和受支持存储，P6 依据可靠性、维护成本与数据策略定案。

密钥默认由各设备重新配置。若需要跨端同步密钥，单独定义端到端加密、设备加入/撤销及恢复策略，不将其混入普通文件同步。

## 7 画布 媒体 CAD 与 3D

画布保留节点与资产模型、连线、生成任务、素材引用、修订、变体、备份和恢复。安卓渲染与输入重新实现；可用的 Web 组件需验证离线资源、桥接、生命周期和性能。每个文档仍只拥有自己的选择与撤销历史。

媒体优先利用系统编解码器和 Media3 完成播放、裁剪、拼接、缩放、音轨与导出。复杂滤镜、字幕和格式缺口使用按需组件或 Linux 工具补齐；Media3 并不自动覆盖现有媒体工作台全部能力。

补帧与超分辨率不属于本地大语言模型，但可能使用本地神经网络。默认不随基础包分发：先提供明确配置的远程路径，若需要离线再单独评估可选组件。这一项不能被“安卓不做本地模型”自动删除，也不默认授权下载推理资源。

CAD/3D 优先复用数据、命令、几何内核和已有可移植前端。DWG、DXF 和原生 `.floecad` 分别验收；不能用 DXF 只读预览替代 DWG 编辑或参数化建模。未实现的格式保持原件，外部查看只是辅助路径。

完成统一模型编辑、装配、图纸、选择高亮、单位、对象保留、分支与导出后，才能关闭工程工作台差异。中文字体、网格/材质、大图纸、旋转和应用重建均列入测试。

设计流程复用简报、冻结输入、候选、对比、采纳、分支、回滚与反馈锚点；文件、附件和画布入口共享契约。生成请求派发后结果未知时先核对，不自动重复付费请求。

## 8 浏览器 远程连接与系统集成

浏览器自动化需要可观察、可操作的受控页面；Custom Tabs 或系统浏览器适合登录和外部打开，但不能被当作完整自动化替代。登录态、下载、文件选择、弹窗、全屏、手动接管与交还分别测试。WebView 桥按可信本地内容与远程内容区分，避免任意网页获得原生工具访问。

本地网页服务限制暴露范围并使用需要的访问令牌。回环地址不等于只有 Floe 可以访问；PRoot 环境之间也不能假定独立网络。远程页面和本地预览采用明确路由。

SSH、VNC、隧道、Telnet、TCP、BLE、邮件和 GitHub 认证按真实协议适配。保存地址不等于可连接，连接不等于命令完成。BLE 扫描、通知、麦克风、日历与附近设备等权限按具体操作申请，拒绝或撤销后可恢复。

日历可使用安卓系统数据能力；提醒没有可直接照搬的 Apple Reminders 存储，因此采用 Floe 自有待办或用户配置服务。工具名称与描述反映真实对象，旧任务记录保持可读，不能把 `apple.*` 悄悄解释成另一账户。

## 9 后台 调度与三星测试

画中画只服务明确的视频或状态显示需求，不参与后台存活、调度、持锁或恢复逻辑；不播放无意义内容以维持进程。辅助功能服务只执行获授权的手机操作，不承担 Linux 或 Agent 的保活。

用户发起的执行、媒体处理、下载和周期工作按适用服务类型实现，不把所有任务套入一个 dataSync 服务。前台通知显示真实工作与停止操作；WorkManager 用于适合的持久延后工作，不保证任意时刻立即执行。

一次、每天、每周、间隔以及指定运行成功后执行一次的产品语义保留，且必须是真实执行而非仅通知：调度的唯一权威仍是共享 Swift 核心（`TaskSchedule.swift`/`TaskScheduleStore.swift` 的 cadence、occurrence 去重、原子 claim 与中断对账语义），Android 侧只做 AlarmManager/WorkManager/JobScheduler/开机接收器的平台适配，不建第二套调度存储或平行运行时。日历型（每天/每周/一次）按锚定时区在触发时重算墙钟时间并处理时区/DST 变化，interval 使用不受改表影响的经过时间语义；“上游成功后执行”由共享完成回调直接入队，重放回调不能重复触发。精确能力按平台资格与授权处理：精确闹钟需用户授予特殊访问，资格缺失或被撤销时降级为灵活窗口并如实显示“将延迟/待执行”，绝不为省权限使用依赖进程存活的监听器型精确闹钟假装准点；周期作业受 WorkManager 15 分钟最小间隔、前台服务类型时限与 Android 16 起的作业配额约束，重复周期用“触发后重排下一次”的一次性机制实现。调度保存模型、环境、工作区、权限与预算快照，实际执行前再次验证；配置、授权被删除或撤销时进入可处理的等待/失败，不静默改用其他账号或模型；调度本身不授予未来执行权限。派发采用至少一次语义：持久去重与原子领取保证同一逻辑 occurrence 只有一个活跃执行属主，但不承诺跨崩溃或远端副作用的 exactly-once；外部结果未知时先查证再决定，不盲目重发。错过的窗口按用户设置合并/跳过/追赶并如实记入历史；应用更新、恢复出厂或新设备恢复后重排且避免重复运行。

App 进程死亡、系统 force-stop、设备重启、撤销权限、断网和省电模式分别定义恢复语义。force-stop 后不承诺自启动；恢复时不能把旧服务端口或旧 PID 当作仍然运行。系统任务管理器对前台服务应用的 Stop 与设置中的 force-stop 不是同一语义：前者立即杀死应用进程并移除通知、不给回调，但已调度的作业与闹钟仍按计划执行，应用下次启动须据 `ApplicationExitInfo` 等原因收敛；后者使应用进入 stopped state 并取消挂起 PendingIntent，不同“停止”入口不合并成一句“已停止”。开机后凭据加密存储尚未可用时任务显示“等待解锁”，不把密钥移入设备保护存储换取提前执行。若某任务依赖用户可选的 ADB-shell 或 Root 后端，每次触发须实际复核该任务所需后端（持久授权记录、在线 shell 桥、Root 后端三种形态分开），仅在所需后端确实不可用（例如重启后桥接未重建）时进入“等待重新激活/重新授权”的可操作状态，不得假装完成；不泛化“重启即全部失效”，也不承诺任何授权必然跨重启持久；两者均不影响普通档任何定时功能。平台约束、设计与未实测边界详见[应用内更新与真实调度调研](FLOE_ANDROID_UPDATE_SCHEDULING_RESEARCH.zh-CN.md)（2026-10-18）。

现有真机为 SM-G9810、ARM64、Android 13/API 33、One UI 5.1、约 12 GB RAM、4 KB 页；设备读取时 `/data` 剩余约 91 GB，内存余量会随工作变化。该机承担端到端、性能和三星后台验收。

## 10 轻量化与组件分发

### 10.1 组件划分

| 层 | 内容 | 默认策略 |
| --- | --- | --- |
| 基础应用 | 云端模型、Agent、内置 IDE、任务、文件、基础预览、设置、能力发现 | 安装即用 |
| Linux 资源 | 已签名清单、ARM64 rootfs、基础包 | 首次执行前准备，可由用户管理 |
| 开发包 | Python/Node 依赖、编译工具等 | 按环境和任务安装 |
| 内置 Office | 安卓原生内核、最小资源与字体；预览、计算、保存与导出 | 优先随包，确认首次离线预览；裁剪与其他签名交付方案按实测决定 |
| 媒体与工程组件 | 额外编解码、CAD/几何等 | 按实际能力拆分 |
| 外部应用 | 人工 Office、专用查看器等 | 用户选择，真实回传验证 |

按需不意味着可以从任意网址下载 `.so` 并加载。原生代码模块采用适用渠道允许的签名分发；Linux 数据、解释脚本、包管理和可执行资源分别对照渠道规则评估。Play Feature Delivery 与 GitHub APK 的安装方式分开设计，不能让 APK 用户依赖只有 Play 安装才有的动态模块。

第一轮发行架构优先限定 `arm64-v8a`，避免将用不到的 ABI 塞入所有下载。开发宿主、模拟器和真机 ABI 分别安排；ARM64 三星结果不能替代 x86 模拟器兼容结论。

### 10.2 初步预算

以下是待 P1/P2 测量校准的工程预算，不是当前测量或对外承诺：

- 无重型可选组件的核心 arm64 下载包以 150 MB 内为初步参考。加入必需原生 Office 后，总下载/安装预算在 P1 根据内核、字体和资源实测重定；此前 100/150 MB 不能作为完整对齐包体承诺。
- Linux、全套媒体扩展与额外开发包不在安装后自动展开；不分发本地大模型。Office 原生预览所需内核和最小资源纳入实际发行预算。
- 运行资源分别显示下载体积、展开占用、已安装包、工作数据和可清理缓存；不把下载缓存当成安装态。
- 核心空闲界面以 PSS 低于约 300 MB 为初步检查线；WebView、Linux 和媒体峰值单独计量并按三星实测设限。
- 首次环境安装预检压缩文件、展开、暂存、回滚和用户数据余量，不能只检查下载文件大小。
- 准备过的环境在已有组件可用时可离线启动；使用云端模型仍需网络，文档和文件的非 AI 功能尽量离线可用。

所有体积数据区分压缩下载、安装后占用、共享缓存和运行内存。轻量化通过真实按需和减少重复引擎实现，不以删掉必需功能冒充对齐。

## 11 分阶段执行计划

### 11.1 执行规则和阶段关系

P0–P6保留为技术工作包与验收台账，共85个工作包。实际推进次序采用第23节的四个阶段、15个串行小目标：先完成全部代码和必要组件验证，再集中端到端联调，随后做视觉/性能调整和测试交付。任务完成状态统一为待开始、实现中、组件验证通过、完整 App 验证通过、三星验证通过、已交付；不能仅凭代码合入标记三星通过。用户已确认计划；G01完成工程、工具链、公共契约、85工作包归属、代表页面门槛和最终证据/清理交接并关闭。当前唯一活动目标为G02，其余目标依序待开始。设备可连接/解锁检查已完成，不等于Android产品验收。

P0–P6表达技术依赖与最终验收关系，不再要求每个P阶段完成全部真机/UI验收才允许编写下一阶段代码。G01先冻结公共边界，各功能目标吸收对应P1探针与P2–P5实现，跨模块及完整设备验收集中到G12/G13；P6中的迁移、更新、反馈等功能代码也必须在G11前完成，不能留到交付阶段才开始写。完整 App 构建、原生重型构建、设备操作与发布由集成负责人串行安排。不同工作包不同时修改同一个核心契约或使用同一可变构建目录。

每阶段以可检查的交付和退出条件收尾，不自动要求用户重复批准范围明确的可逆工作。新增账户/敏感权限、购买服务和其他未覆盖的外部后果到实际发生时单独处理；Android GitHub阶段发行已按第23.1.1节获授权。失败项先收敛到明确的依赖或缺陷，保留可恢复产物后继续，不用盲目重复构建代替定位。

## 12 测试和验收标准

### 12.1 必测端到端场景

1. 自配云端模型，长流式回答，途中追问与取消，断网恢复后不重复执行工具。
2. 导入项目、编辑脚本、安装依赖、执行、读取完整输出、导出成果。
3. 两个子代理共享环境，取消一个不影响另一个；停止环境全部退出。
4. 断网并关闭 Linux/外部编辑器，内置 Office 仍显示三类文档；引擎进程终止后保留恢复副本；外部编辑补充路径在原件并发修改时保留两份。
5. Excel 写公式后由真实后端重算，检查缓存结果和错误；文档导出 PDF 后逐页核验关键布局。
6. 手记导入、书写、助手修改、撤销、封面、导出重开；删除源聊天不删除资料。
7. 画布生成、未知结果恢复、素材下载、分支、保存、备份恢复；不重复计费提交。
8. CAD/3D 修改、单位、保存、重开、导出；未知对象不被展平或丢弃。
9. 媒体项目保存、字幕音轨、导出、播放核对；失败或取消保留原素材和恢复状态。
10. 浏览器登录接管、全屏、交还、下载、回原任务；密码和表单内容不进入日志。
11. 调度到期、锁屏、省电、断网、重启、force-stop 后恢复；不伪造按时执行。
12. 临时会话的旋转/锁屏保持、实际导航销毁、晚回调隔离和保留失败重试。
13. 撤销文件/麦克风/通知/日历权限、磁盘不足、rootfs 下载中断、组件升级失败可恢复。
14. 从旧 APK 升级，任务、项目、手记与环境安装态保留；卸载组件不会删除文档。
15. 关闭 PiP，分别测试 Agent/Linux、媒体、下载、调度的前后台、锁屏、强停与恢复；无隐式 PiP/辅助功能保活依赖。
16. 手机操作在授权应用上完成观察、点击、输入、滚动、返回和切换；用户接管、停止、权限撤销和锁屏时停止后续动作，旧页面/旧节点不可继续重放。

### 12.2 性能与资源

测量冷启动、首批历史、长对话滚动、PRoot 冷/热启动、Python CPU 工作、包安装、小文件读写、Node 服务、Office 打开/保存、媒体导出、峰值 PSS、CPU、温升和耗电。每个结果记录设备、系统、源 SHA、构建方式和样例。

先建立三星基线，再设发布阈值。CPU 模拟与原生执行的比较要注明不同设备差异；更可靠的后端比较优先在同一台设备完成。不能把几秒基准推广为所有任务的节省倍率。

### 12.3 构建与证据

保持锁定依赖和组件摘要。Android/Swift/NDK/Gradle 的重型构建与 iOS 发布编译串行安排，缓存放项目约定的内置 SSD 独立目录，先以受控并发测资源。

每阶段保留源 SHA、工具链、APK/AAB、符号、组件版本、测试命令、原始失败与回归结果。完成后导出必要证据，清理本任务已确认不用的可再生输出。三星测试与模拟器证据明确区分，模拟器在完成且无其他使用者时关闭。

### 16.3 对现有 Floe 的具体复用判断

当前 IDE 的归属记录位于 `FloeAgent/FloeApp/Resources/IDE/NOTICE.md`：已有CodeBlitz/OpenSumi Monaco离线资源、原生文件适配与应用集成。这些经验可复用，但Monaco移动支持限制使其仅进入对照，不能预设为安卓默认。Sora优先验证，CodeMirror作为第二候选；实际选择由三星输入法、选择/滚动、撤销、性能和接入成本决定。

当前FloeCADKit使用OCCT 7.8.1 iOS二进制、Objective-C++桥、Accelerate数学调用和Metal/UIKit渲染。几何算法不是全部重写，但现有包也不是纯Swift直接跨编译：OCCT必须出安卓产物，数学实现和渲染分别替换。Filament只能减少渲染工作，不能替代建模特征、装配或图纸输出。DWG读写也不能仅凭OCCT存在判定可用。

Office复用现有命令和成果校验，原生内核、JNI/资源和视图仍需安卓适配。AndroidX PDF与Ink可降低阅读/书写基础工作，不接管Floe手记的文档、助手、撤销和引用关系。媒体复用Media3和按需FFmpeg后，项目模型/时间线/作业恢复仍需接入。

现有Runtime、Provider、工具协议、文档/设计命令、所有权与修订规则优先共享。不要同时引入Room作为另一个业务数据库；安卓组件可使用自己的可重建缓存，但不能再创建与Floe历史竞争的任务真相。

邮件、SMB、WebDAV/S3、归档与跨端同步优先核对当前已锁定实现的可移植性。没有完成候选源码、许可与设备验证的部分保留为选型任务，不声称已经找到可直接替代整个工作流的库。系统日历/待办、通知、分享和调度优先正式安卓API。

### 16.4 语言服务 终端与执行的连接

Sora的editor-lsp或Web编辑器LSP桥不包含所有语言服务器。按需在选定ARM64环境安装受支持的Python/TypeScript等服务器；stdin/stdout或受控本地通道连接，服务器工作目录、文件URI、版本号和取消归属同一环境。

建立Floe文档ID → 本地工作副本 → Linux可见路径的显式映射；SAF文件不能直接传给Linux LSP当真实路径。处理UTF-16位置、中文/emoji、换行、didChange版本、workspaceEdit修订与诊断过期。AI和LSP补丁走同一写入协调，不分别覆盖。

Termux terminal-view/emulator只承担显示与终端协议；运行仍经过Floe exec.shell和jobs。核对TerminalSession是否默认自行创建进程、PTY和运行器；必要时写窄适配以接Floe后端，不直接引入完整Termux服务。原生Termux包路径、Android Bionic与Debian/Alpine不能混为一个安装层。

### 16.5 新增手机操作架构

完整APK内置独立的手机操作模块，通过系统AccessibilityService提供观察、节点定位、点击、输入、滚动、返回、应用切换与适用截图。优先结构化节点，必要时使用用户授权的视觉观察；自绘页面、WebView、受保护窗口和节点缺失准确报告限制。

观察带taskID/runID、包名、窗口ID、时间、页面generation和短期节点引用；每次动作前重新确认窗口/目标与观察仍匹配。手势完成回调只代表输入派发完成，必须再次观察以确认结果；超时、页面变化或异常弹窗先重观测，不盲目重放潜在外发/付费动作。

操作权限由用户任务、目标应用范围与系统服务启用状态共同决定。用户接管、一键停止、任务结束、权限撤销或设备锁定立即阻止后续动作；恢复需重新观察，不继续旧点击队列。选择器/屏幕文本不授予权限，界面中的提示词不能改变任务目标。

敏感外发、付款、账户/安全配置和破坏性操作继续走对应明确授权；普通已授权导航/输入不逐次重复审批。密码字段不读取、截图不用于采集锁屏PIN，诊断不留原始敏感屏幕。发送屏幕/节点内容到云端模型前明确该任务范围和数据用途，限制上传区域与保存期。

采用API级别检测：三星API33可以验证显示截图和节点/手势；API34新增的单窗口截图及安全窗口错误码等不能直接下调用。安全窗口失败即报告，不绕过系统保护。开发主机ADB解锁能力不作为发行App可解锁或后台操控锁屏的证明。

服务启用由明确披露和用户系统授权完成；计划本身不预先打开服务。AutoJs6/GKD只提供选择器、事件去抖等参考，不能把它们的任意JS/规则下载权限接入Agent；语言代码继续使用既定Linux执行服务。

### 16.6 完整 APK 与 Google Play 构建边界

按用户2026-10-18指定，采用两个产品变体：`full`保留手机操作，`play`彻底排除该模块。`full`表示功能范围，不表示已公开发行；命名、applicationId与签名在P0冻结。

将接口/不可用实现与真实实现分开：共同核心使用平台能力接口，`:phone-control`和`:root-system`实现及其依赖只进入GitHub full的构建图，play采用明确不可用实现或不注册相应能力。不要只使用运行时开关隐藏入口。

| 检查对象 | full | play |
| --- | --- | --- |
| 模块与依赖 | 编译手机操作及Root实现和必要资源 | 不解析/打包两模块专属代码、资源和传递依赖 |
| Manifest | 实际需要的AccessibilityService、BIND_ACCESSIBILITY_SERVICE与配置 | 无该服务、绑定权限及配置资源，无专属组件 |
| 模型工具与Skills | 手机操作或Root服务各自已启用且授权时发现对应能力 | 工具目录无手机控制/Root专属能力；共用Skill按能力过滤 |
| 页面和说明 | 启用、披露、任务范围、停止和诊断 | 无不可用死入口、授权引导或手机控制承诺 |
| 更新与安装 | 已授权渠道的签名APK；App内更新器只信任官方GitHub发布通道，手动检查与用户控制的自动检查/下载/安装并行存在，安装经PackageInstaller会话并区分下载取消与已提交会话语义 | Play候选AAB及对应安装包；更新只走Google Play机制；更新器模块、feed/仓库常量、REQUEST_INSTALL_PACKAGES与UPDATE_PACKAGES_WITHOUT_USER_ACTION全部物理排除并按P6.7同法核验Manifest/DEX/依赖 |
| PiP与辅助服务 | 两者均不作通用保活 | 不依赖PiP，也没有手机操作服务 |

P6检查Gradle依赖图、合并Manifest、最终DEX/资源、组件清单和运行工具发现；证明play产物没有手机操作和Root增强模块，不能只用源码条件判断。同一方法自2026-10-18起亦须证明play产物物理排除GitHub更新器模块及其依赖、feed/仓库标识、安装类权限与入口；这不是运行时隐藏。Play版不通过远程下载、动态模块、伴侣插件或跳转安装来恢复被移除能力。官方政策原文（2026-10-18核对）禁止经Google Play分发的应用以Play机制之外的方式自我更新或从外部下载可执行代码；VM/解释器内运行代码另有例外，仍按第10.1节渠道规则逐类评估。full侧自更新的信任链、续传校验、安装会话与免确认门槛见[应用内更新与真实调度调研](FLOE_ANDROID_UPDATE_SCHEDULING_RESEARCH.zh-CN.md)。

优先评估两个applicationId以便三星并装、独立数据和独立权限；是否采用相同ID/签名替换需在P0明确。跨变体资料通过版本化导入导出；不假定能共享私有目录，不覆盖用户现有数据。移除模块导致的历史手机操作任务保持可读，Play中明确不可继续，不重复执行。

Google Play当前对使用辅助功能自主规划并执行动作有明确限制；用户同意不自动豁免。完整APK也继续遵守操作系统和其分发渠道要求，不伪装残障辅助工具、不绕过安全控制。[Google Play原始政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)

### 16.7 后台执行不依赖画中画

Agent、Linux、下载、媒体与调度采用各自适用的前台服务/系统任务与持久作业。前台服务类型按真实用途决定，不能选择不相关类型获取更长运行；不存在“通用无限AI服务”保证。

状态显示可使用通知及App内面板；需要停止操作时提供明确入口，不把浮窗权限设为核心执行前提。PiP存在与否不改变任务所有权、锁、检查点、调度或恢复。手机操作服务仅在相应功能授权中工作，也不用于维持其他进程。

加入独立验收：关闭PiP且不启用辅助功能，测试聊天/IDE/Linux/Office/下载/媒体/调度；再启用手机操作测试跨App流程。锁屏、断网、系统回收、强停、重启、服务断开分别验证。强停与锁屏不承诺仍能控制其他App或精确按时执行。

### 16.8 复用验收与工作量调整

每个候选按五项放行：固定版本和许可证、最小可构建宿主、三星真实功能、与Floe所有权/取消/保存接通、资源与升级恢复。原生依赖加16KB与符号；GMS类能力增加无GMS设备/环境路径验证。本轮只确认三星装有GMS包，不将其视为GMS健康、OCR可用或其他安卓设备具备GMS的证明。

P0.6负责全产品复用台账；P1.8覆盖IDE/终端/LSP，P1.9覆盖PDF/Ink/OCR/媒体，P1.10覆盖几何/远程，P1.11覆盖手机操作与分发接口。后续工作包以选定组件接入，不再默认重写对应底层能力。

复用减少编辑器、终端协议、PDF基础、笔迹、媒体及传输实现量；主要投入转为JNI/依赖构建、平台输入与生命周期、数据兼容、Agent契约及集成验收。当前总估算保持带风险的预算，P1后按实际工作包剩余量重算，不在只有候选资料时宣称节省固定百分比。新增手机操作与full/play产物验收单列增量，不与原功能重复计费。


## 17 安卓系统体验与交付专项

### 17.1 系统设计原则与当前结论

安卓版本需要完整的系统体验：用户看得见正在运行什么，能从通知和App控制，切换应用不丢任务，文件和账号权限有清楚归属，升级与设备更换后资料可恢复。持续通知是产品功能和适用前台服务的一部分，不是永久保活保证。PiP与辅助功能不承担其他任务的保活。

截至2026-10-18官方资料已发布Android17/API37，Play普通手机应用提交基线要求target API36或以上。实施时区分compile SDK、target SDK、min SDK与设备系统；不能只在三星Android13上跑通就判定高target行为通过。优先使用当前稳定工具链；本轮以compile/target API37为默认目标并落实其新特性与行为，API36仅作为当时Play最低要求和兼容检查参考。若工具链或已锁定引擎存在具体阻碍，先记录并修复；确需暂用较低target时写明原因与升级工作，不静默以最低target作为最终方案。发布前复核渠道要求，不通过降低target绕过系统权限。[Android17发布](https://developer.android.com/blog/posts/android-17-is-here) · [Play目标API要求](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)

本节将可由文档定案的设计明确下来，将需要构建/设备确认的内容绑定工作包。没有可执行App的项目不得写成设备验收完成；这也不意味着需要关闭已实现功能等待所有硬件反馈。

### 17.2 持续通知与运行中心

**默认设计：** 真实进行中的后台工作显示运行通知；任务完成/失败/需要用户处理使用独立事件通知。空闲时不启动FGS只为显示“Floe在线”；若用户需要常用入口，可提供普通通知或快捷入口，但不宣称其维持执行。

| 渠道 | 内容与默认行为 | 操作 |
| --- | --- | --- |
| 正在运行 | 低打扰，真实阶段、运行数、可测进度/时长；无正文和路径 | 打开运行中心；支持安全停止的目标可停止 |
| 需要处理 | 审批、登录、权限或环境问题，去重并说明行动 | 进入正确任务的对应步骤，不在锁屏直接扩大授权 |
| 已完成 | 成果数量/类型和任务完成，用户可关闭或静音 | 打开任务/成果 |
| 失败与恢复 | 可操作错误、需要恢复的工作；不泄露命令正文 | 打开详情或安全重试入口 |
| 调度提醒 | 等待启动/错过等真实调度状态 | 查看/按规则立即运行；提醒不冒充执行 |
| 手机操作状态 | 仅full且服务/任务实际启用时显示所需状态 | 停止当前操作/手动接管；不作为其他作业保活 |

持久任务登记是通知数据源，通知不单独维护另一套状态。每个动作绑定task/run/job ID和当前generation；完成/归档/删除/换代后旧按钮失效。PendingIntent身份和不可变性按实际动作设计；打开走Activity深链，停止走有界服务/接收端，拒绝伪造外部Intent。多个任务共享汇总时，停止一个不会关闭其他任务所需服务。

只提供真实可实现的动作：无检查点的任意进程不显示“暂停后无损继续”；停止是请求，收到执行器确认才报已停止。运行期间节流通知刷新，不随每个token振动或发新通知。进度未知时使用不定进度和已知阶段，不伪造百分比。

Android13+的POST_NOTIFICATIONS可被拒绝，FGS仍需按规则提交通知，用户可能仅在系统任务管理器看到它；App中保留运行中心、停止与权限状态。通知渠道可被用户静音/关闭，不重建新channel规避选择。锁屏使用最小公开版本，默认不展示对话、文件名、账户或其他App屏幕；进入敏感详情后再要求合适解锁。

Android14起一般ongoing通知可在解锁状态由用户移除，因此“持续”不承诺不可划走。移除通知、停止作业、系统任务管理器停止App和设置中的force-stop分别处理。Live Updates/进度通知仅在系统支持且用例符合资格时增强，不能依赖它做基本控制，不伪装通话或媒体通知来获得特殊待遇。

依据：[通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission) · [通知渠道](https://developer.android.com/develop/ui/views/notifications/channels) · [通知导航](https://developer.android.com/develop/ui/views/notifications/navigation) · [ongoing通知变化](https://developer.android.com/about/versions/14/behavior-changes-all) · [Live Updates](https://developer.android.com/develop/ui/views/notifications/live-update)

### 17.3 后台服务选择与生命周期

**执行分类：** 可恢复有限作业使用系统调度；用户明确启动且持续可见的工作按真实用途使用适用FGS；远程已提交作业可以在本机停止后继续由服务器拥有，本机恢复查询而不伪造本地驻留。

| 实际工作 | 候选执行位置 | 必须核实的条件 |
| --- | --- | --- |
| 上传/下载/备份 | 可恢复传输、适用UIDT或dataSync | 用户发起条件、约束、校验和、断点、系统版本 |
| 媒体导出 | 适用mediaProcessing/对应旧系统路径 | 类型/超时、取消、文件暂存与真正导出完成 |
| 真实音视频播放 | MediaSession/适用mediaPlayback | 真正播放用途，不播放静音以保活 |
| 录音 | 用户在可见界面启动的录音及适用microphone | 使用中权限、停止、后台启动限制 |
| 手机操作 | 系统绑定的AccessibilityService及其授权任务 | 生命周期独立，不用于Linux或Agent保活 |
| 日常聊天/IDE界面 | App可见会话及服务自有状态 | 页面销毁不丢草稿/任务；后台执行另外判断 |
| 长Agent/Linux交互与本地服务 | P1核实适用FGS类型与可见会话设计 | 没有天然通用“AI服务”类型；specialUse须真实用例/声明/渠道资格，不假定自动通过 |
| 周期扫描/清理/同步 | 可延后且有约束的WorkManager/JobScheduler | 不保证精确到秒、幂等、退避、去重与批量合并 |

如某类长期交互无法满足目标系统/渠道资格，保留前台交互、可恢复的后台有限作业和显式远程服务路径，说明实测限制；不能仅增加一条常驻通知就承诺无限后台运行。该决策必须在P1.12结案，不能拖到发行才发现。

dataSync与mediaProcessing在适用新系统有累计时限；后台发起FGS受限制，开机广播不能任意恢复各类FGS。Android16起长WorkManager作业即使内部使用FGS也可能耗尽job配额。定时到点只能在满足平台条件时开始，否则保留等待和通知；不靠循环唤醒或反复重启规避限制。

生命周期记录分为用户停止、任务取消、超时、进程回收、系统任务管理器停止、force-stop、重启、升级与权限撤销。系统任务管理器停止App可能不回调清理；重开从持久作业与ApplicationExitInfo核对，不能依赖onDestroy。force-stop后不保证自动恢复；开机后锁定凭据数据仍不可用时不启动需要密钥的工作。

依据：[FGS类型](https://developer.android.com/develop/background-work/services/fgs/service-types) · [后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) · [时限](https://developer.android.com/develop/background-work/services/fgs/timeout) · [用户停止App](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping) · [长Worker配额](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running) · [UIDT](https://developer.android.com/develop/background-work/background-tasks/uidt)

### 17.4 三星省电 子进程与资源

三星测试分为默认设置、用户选择的后台优化设置、系统省电/低电量与受限状态，不将Never sleeping或“不受限”设为所有功能的首次启动必需条件。确实需要时在任务相关位置说明用途与系统路径，记录设置前后差异；不会因为加入从不休眠列表就声称绕过Android全部限制。

PRoot/编译器/LSP会派生子进程；除普通LMK和内存压力外，还要测试Android的phantom子进程治理。使用有界并行、限制闲置LSP与服务数、输出背压、每任务句柄和检查点，不要求用户关闭系统子进程限制。以实际PID加进程创建身份/会话generation核对，避免PID复用误杀。

Wakelock仅为必要、可见且有超时的工作持有，完成、取消和失败均释放；Wi-Fi锁、Doze豁免不作为默认万能方案。热状态、CPU、内存和磁盘压力进入自有资源调度，限制重型Office、媒体和多个Linux任务叠加，不强停其他App。

依据：[三星应用管理](https://developer.samsung.com/mobile/app-management.html) · [Doze](https://developer.android.com/training/monitoring-device-state/doze-standby) · [Standby buckets](https://developer.android.com/topic/performance/appstandby) · [AOSP子进程治理源码](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/am/PhantomProcessList.java)

### 17.5 权限和原生系统入口

权限按能力出现，拒绝后保持其余功能可用。基础聊天、IDE、手记与Office不要求通知、辅助功能、全盘访问、麦克风、位置、悬浮窗或全量应用列表全部授权。通知权限在有价值的后台/提醒场景请求，用户拒绝时仍可前台使用。

原生入口包括ACTION_SEND/SEND_MULTIPLE、打开方式/ACTION_VIEW、系统选图/文件、拍摄导入、向其他App分享、快捷方式/小组件或快捷设置的适用入口。优先分享和正式Intent/API解决已知操作；跨App视觉操控是full的补充路径，不用来替代每一个可以直接完成的集成。

收到分享时先显示来源与目标任务/项目，处理文本+URI、多附件、只读流、超大文件、文件名冲突和短期授权；选择保持原地引用或导入副本。接收不等于自动发送模型/执行命令。来自外部的MIME、文件名、HTML和深链参数均不可信，验证内容、路径与大小，不信任外部自报taskID自动获得访问权。

深链仅路由到用户可访问对象，敏感动作不由一个URL直接触发。已删除/归档/迁移目标有正确返回路径；冷启动和已有任务栈均测试。Google/Provider OAuth采用受支持认证浏览器与PKCE等实际流程，登录不从普通网页桥泄露令牌。

full侧载可能触发系统“受限设置”，提供实际可用的系统授权引导，不利用ADB设置替代正常用户路径；测试机ADB成功不代表发行安装流程成功。剪贴板读取只在明确操作发生，截图/最近任务隐私按产品敏感范围控制；不默认监听其他App通知或索取通知访问权限。

依据：[分享接收](https://developer.android.com/develop/ui/compose/sharing/receive) · [深链风险](https://developer.android.com/privacy-and-security/risks/unsafe-use-of-deeplinks) · [受限设置](https://support.google.com/android/answer/12623953?hl=en)

### 17.6 网络与本地服务

覆盖Wi-Fi/移动网络切换、网络可用但未验证、门户登录、VPN/代理/Private DNS、IPv4/IPv6、DNS失败、TLS、自定义端点、本地明文HTTP、计费/流量节省和后台数据限制。重连先查远端请求/作业状态，不能盲重发付费生成、邮件发送或提交。

默认安全TLS，不全局信任用户证书或关闭校验；开发环境证书/端点通过限定配置处理。对本地网页服务和用户明确配置的设备，按必要域/用途评估明文访问，不开放全应用明文默认。

Android17/API37的网络安全配置还包含默认启用的证书透明度（CT）、取决于网络库支持的ECH，以及localhost的专门默认配置。分别核验Java/WebView、Swift FoundationNetworking/libcurl和Linux环境的实际生效路径，不能以一份宿主XML或本机回环HTTP成功替代证书链、主机名和真实HTTPS验证。新系统按实际支持使用新能力；旧系统及未支持ECH的网络库保留正常安全TLS路径，不把这些特性写成所有版本已具备。依据：[网络安全配置与版本行为](https://developer.android.com/privacy-and-security/security-config) · [系统定义的本地网络范围](https://developer.android.com/privacy-and-security/local-network-definition)。

Android17且target37起LAN保护影响SSH/VNC/SMB/MCP、本地设备和WebView等路径；target36及以下和Android16 opt-in行为不同。不要对所有版本一律请求ACCESS_LOCAL_NETWORK。局域网权限与普通互联网错误区分，PRoot原生socket也不能假定绕开宿主限制。 G02 的局域网 MCP 与本地云模型端点同样受限，须随实际连接入口接入声明、按需授权、拒绝/撤销恢复与旧版回退，不能等到网络工作台或 G11 才补；公网云服务不能依赖这项授权。依据：[Android 本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission)。

模拟器的127.0.0.1、宿主映射地址与三星localhost含义不同。Linux/Office/WebView/IDE预览的监听地址、端口令牌、代理和可访问范围逐条记录，防止开发机桥接配置误入发行包。网络服务默认只暴露所需范围，用户明确要求后才开放局域网访问。

无GMS时正常保留云端模型、IDE、Office和核心任务；推送、系统语音、OCR等探测实际能力，提供bundled/配置路径，不能静默换未经同意的云端服务。不会为了后台轮询默认建设必需的Floe云端账户或FCM依赖。

依据：[LAN权限与版本条件](https://developer.android.com/privacy-and-security/local-network-permission) · [WebView宿主行为](https://developer.android.com/develop/ui/views/layout/webapps/webview)

### 17.7 数据 凭据 备份与升级

确定私有文件、SAF引用、缓存、rootfs安装态和文档成果的边界。数据库迁移、组件更新和rootfs更新分版本；更新前暂停/排空实际持有者，失败保留原件与恢复点。删除环境/组件不能删除仍被引用的用户成果。

Android Keystore用于保护凭据，结合加密记录和最小授权访问；不把所有API调用绑定每次生物认证而使用户允许的后台任务无法执行。设备重置、锁屏方式变化或密钥失效按实际情况提示重新配置凭据，文档不随之删除。

Auto Backup和设备迁移不能直接带走设备绑定密钥或全部rootfs。明确备份排除项：凭据、临时会话、可重建缓存、运行句柄和大资源；用户资料使用受控版本化备份/导出。恢复后的密文无法解密时要求重配密钥，不尝试将错误数据当明文；系统备份不是Floe完整资料备份承诺。

full/play应用ID、签名、Provider authority、回调URI、文件分享和导入导出命名均独立或明确兼容。优先双ID并装以便三星比较；决定后保证签名与versionCode连续，不通过卸载清数据完成升级测试。Play App Signing与完整APK签名路径分开记录；渠道互换不能假定直接覆盖安装。full 包应用内升级另须：候选 APK 实际签名与已安装版本签名 lineage 一致，校验和只证明完整性、不能替代来源真实性；Android 14 起跨安装器 update ownership 可能要求用户同意；开发者验证自 2026-09-30 起在部分区域对认证设备生效并于 2027 扩大，更新器须把验证失败/需用户确认作为一等可解释结果（门槛细节与来源见 2026-10-18 的[应用内更新与真实调度调研](FLOE_ANDROID_UPDATE_SCHEDULING_RESEARCH.zh-CN.md)）。

发行检查还包括16KB原生库、split APK/AAB资源、R8/JNI保留、native symbols、依赖资源许可证、敏感配置、Play数据安全表与完整APK的适用开发者验证要求。不在研究阶段创建账号、修改签名或公开上传。

依据：[Keystore](https://developer.android.com/privacy-and-security/keystore) · [Auto Backup](https://developer.android.com/identity/data/autobackup) · [开发者验证](https://developer.android.com/developer-verification) · [16KB](https://developer.android.com/guide/practices/page-sizes)

### 17.8 平板模拟器建设与无平板真机方案

2026-10-18检查：Mac为ARM64、24GB内存，内置盘可用约85GiB；PATH、Android环境变量、常见SDK/AVD/Homebrew/Android Studio目录未发现可用模拟器工具链。该结果只覆盖已检查路径，P1.13先完成工具链定位/安装，不将ADB已安装误当成已有Android SDK与AVD。

Apple Silicon使用ARM64镜像及macOS Hypervisor.Framework加速，先运行accel-check和实际APK启动；不能用x86镜像可创建代替可加速运行。开发机虚拟化与发行APK内能用AVF是两回事。

**最低可执行矩阵：**

| 配置 | 用途 | 执行策略 |
| --- | --- | --- |
| 三星API33/4KB | 真实任务、终端/Office、性能、锁屏/省电、辅助功能与升级 | 主要真机，不改系统或清用户数据 |
| 最新稳定Android ARM64平板主AVD | 新原生特性、大屏导航、IDE面板、Office/PDF、手记、画布/媒体/CAD | 先建一个，覆盖横竖屏、全屏/分屏和窗口缩放 |
| API36兼容镜像与API37主镜像 | 新旧路径、目标API行为、服务/通知、LAN、后台、系统权限 | 共享可用镜像，按阶段串行启动，不常驻多台 |
| 16KB ARM64镜像 | Swift/JNI/LOK/OCCT/编解码等直接和传递库 | 采用实际支持镜像，getconf PAGE_SIZE确认16384后测 |
| 无GMS系统配置 | 核心功能与可选服务缺失路径 | 按需启动，不能仅禁用一个包就宣称完整无GMS覆盖 |
| 折叠/桌面窗口配置 | 动态大小、面板、焦点和返回导航 | 优先复用主镜像和调整配置，必要时独立AVD |

平板布局按当前窗口宽度而非机型判断，测试compact/medium/expanded及断点两侧、横竖屏、1/2和窄分屏、自由窗口、字体放大、系统栏与键盘遮挡。尺寸变化保留正在编辑的草稿、光标、撤销、终端、Office会话与画布状态；同文档多窗口必须协调，不能创建两个互相覆盖的独立真相。

键盘/鼠标测试包括中文IME合成、Ctrl/Tab/方向键、右键菜单、滚轮/触控板、拖放、焦点、快捷键和系统返回/预测返回。不能把注入字符测试当完整中文输入法验证。手指书写可以测；压感、笔倾角、掌托拒触、蓝牙笔按钮、Samsung DeX和真实GPU/编解码性能需要用户真实设备体验补验。

初次AVD按工具支持的有效配置设置，普通平板先以4个vCPU、约4GiB内存为候选并测资源，不为16KB镜像强降其最低要求。控制镜像、userdata和snapshot数量，安装前重新测盘；85GiB余量接近父卷80GiB保留目标，评估增量并按项目规则清理确认不用的缓存，不删除其他任务产物。一次运行一个安卓模拟器，避免与iOS重型构建叠加。实际SDK/镜像/AVD位置与缓存策略记录，任务结束关闭自有实例，保留有用资料而非清空模拟器。

平板模拟器通过基本功能/数据/布局后正常开放功能，不设置“等拿到平板真机才解锁”。真实用户反馈用于发现硬件差异和改进体验；不会将模拟器帧率称为平板实测性能。

依据：[模拟器加速](https://developer.android.com/studio/run/emulator-acceleration) · [AVD管理](https://developer.android.com/studio/run/managing-avds) · [窗口大小](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes) · [多窗口](https://developer.android.com/develop/ui/compose/layouts/adaptive/support-multi-window-mode)

### 17.9 功能开放与用户反馈

“未拥有某设备”与“功能不可用”分开。已实现、基本测试通过且无已知严重数据风险的功能在正常入口开放，不长期藏在开发开关；首次使用说明仅提供必要的依赖/配置，不满屏铺测试免责声明。暂缺物理笔或复杂特定文档反馈记录于兼容报告，不用来关闭整类手记/Office/媒体/CAD功能。

确实未实现的操作不做假按钮；缺组件/账户/权限时提供安装、配置、授权或可用替代路径。模型工具发现只提供当前实际可用能力，设置与功能入口可以展示准备方式，不能为了“全开放”向模型宣告不存在的能力。full有手机操作，Play按用户要求彻底去除该模块，其余已实现功能不顺带削减。

反馈入口可从任务、IDE、Office、手记、画布/媒体/工程和设置进入，自动准备非敏感环境信息：App变体/版本、系统/API、设备型号、窗口大小、可选组件版本、错误码与操作阶段。用户补充期望/实际结果、复现步骤与是否可重复。截图、录屏、正文、文件、语音和其他App界面都由用户主动选择，发送前可查看/删减，不默认上传。

对用户提交样例建立事件ID、影响范围、复现/未复现、修复版本与回归用例。数据损坏/误操作优先止损并保留原件；硬件手感问题按设备/笔/系统归类。不会因一个文档失败关闭所有格式或整个App。修复后通过发布说明/原反馈渠道回告；本计划不授权未经请求给外部用户发消息。

公测的实际分发仍按用户指定渠道和发布授权执行。测试覆盖报告显示三星/模拟器/用户设备的不同证据，不把“用户可体验”改写成所有设备已验收。

## 18 新系统原生特性优先与老版本兼容

### 18.1 产品目标与SDK策略

用户要求同时做到旧系统可用和新系统体验充分。产品以当前稳定Android原生能力设计，Android13三星验证兼容；最新稳定Android平板AVD验证新特性。测试最新系统不是只证明旧实现能运行，而是确认新API和交互确实启用。

本轮调研时最新稳定版为Android17/API37，默认计划采用相应稳定compile/target工具链。Google Play最低target要求只是分发下限，不作为主动停留旧API的理由；最低运行版本与target分开决定。所有稳定新能力按实际适用性采用，不为“追新”引入无产品价值的权限、实验框架或本地大语言模型。

共享业务通过平台能力接口调用；各功能独立选择增强实现与兼容实现。禁止一个全局oldMode把新系统全部降到Android13能力。旧版回退保留数据、结果、任务与权限语义，允许界面和执行机制不同；真做不到的能力说明具体限制，不伪造等效。

### 18.2 原生特性采用矩阵

| 功能 | 新系统优先采用 | 老系统回退 | 验收 |
| --- | --- | --- | --- |

| 对外系统能力 | 可用时评估AppFunctions等结构化入口 | App快捷方式、分享、Intent或既有MCP契约 | 验证发布/调用方资格；不把新API当Play版任意手机控制替代品 |

矩阵中有条件的增强，实施必须得出采用/不适用及原因，并记录验证状态。稳定、适用且能增加产品价值的增强正常接入；实验或系统特权能力不作为核心使用前提。Handoff/AppFunctions等不能凭接口存在就承诺所有普通App可自由互调。

### 18.3 实现与兼容规则

- 系统API检查SDK；回移API检查SDK Extension；WebView检查实际WebViewFeature；Jetpack/NDK/硬件能力检查对应运行条件。不能只依据手机型号、target或一个版本号判断所有能力。
- 新版类型与调用隔离到受保护实现，避免旧系统类加载、JNI符号或资源解析提前触发；使用AndroidX兼容层时验证它确实提供所需行为。
- 不支持某增强时保留原任务与文档身份，自动选择兼容实现，不让用户手动切换“旧版模式”。可在诊断显示当前实现；不在日常界面暴露API内部术语。
- full/play和新/旧系统是独立维度：同一平台增强在两版尽量共享，手机操作只存在full，不因为Play移除它就删除其余新版体验。
- 权限拒绝、组件缺失、网络不可用、系统功能禁用和API不支持分别处理；有可用回退则继续，需用户配置则提供明确入口。
- 新系统强化的资源、后台和隐私限制与新功能同时适配，不只使用新API却忽略新行为。不修改系统设置绕过兼容问题。

### 18.4 逐阶段落地与双路径测试

P0.7登记每项特性、引入版本/Extension、组件版本、权限/资格、增强实现、回退实现、负责工作包与用户价值。P1.14在最小宿主里证明两条路径，P2.10开始进入真实App；文档、媒体、工程和系统集成随各阶段接入，不全部拖到P6。

P6.10使用同一源码、同一发行variant在最新平板AVD与三星上跑共同样例。记录实际选中的能力分支、界面/结果和退回原因；版本判断代码存在不算增强通过。涉及API34/35/36差异的分支按最少必要镜像补测，16KB独立验证。

模拟器不支持某物理能力时，保留已实现的正常功能入口和可靠回退，通过用户真实体验补验。缺少平板真机不成为取消新版布局、手记或笔输入支持的理由；未测压感不写成已实测。新特性和用户反馈状态均进入交付覆盖报告。

参考：[Android17新特性](https://developer.android.com/about/versions/17/features) · [Android16新特性](https://developer.android.com/about/versions/16/features) · [Live Updates资格与接入](https://developer.android.com/develop/ui/views/notifications/live-update) · [当前窗口能力](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)。具体API与权限在固定工具链上核实；采用新特性不改变原有“不做本地大语言模型、PiP不保活、Play移除手机操作”的边界。


## 19 网络工作台与 Wi-Fi 分析

### 19.1 产品定位与实现分层

网络是安卓重点能力，设独立网络工作台，并向Agent提供相同服务的结构化工具，不能只在Linux终端里放几个命令。基础网络、Wi-Fi分析、文件与设备连接在无Root且不启动Linux时可用；Linux扩展和GitHub Root只增加能力，不成为基础依赖。

当前源码已有network.ping、network.traceroute、network.dnsLookup、network.tcpProbe，实际使用Darwin/Apple路径。复用参数和真实结果语义，安卓实现另做适配；不因同名工具就把远端/来宾测量标为手机直测。

每次测量记录来源（手机原生/Linux环境/SSH主机/Root）、Network标识、接口、协议、目标、起止时间、配置、采样/退出结果、缓存年龄和权限状态。DNS、连接与数据传输应使用一致且明确的网络路由；原生Network.bindSocket等不能自动影响另一个PRoot进程，未能固定路由时准确报告系统默认路径。

### 19.2 内置功能清单

| 组 | 必需功能 | 数据与结果要求 |
| --- | --- | --- |
| 网络总览 | Wi-Fi/蜂窝/以太网/VPN、IP/掩码/路由/DNS、网络验证/计费/代理/Private DNS可用信息 | 来自实际API，可脱敏导出；权限删改字段不冒充真实空值 |

| 周边AP | 扫描列表、安全类型、频段/信道/带宽、排序筛选、更新时间 | 每AP时间戳，扫描失败/限流/旧结果明确标识 |
| 信道分析 | 2.4/5/6GHz适用信道图、重叠与AP强度、时间曲线、可解释信道建议 | 图来自真实扫描；重叠评分是估计，不冒充噪声/射频占空比 |
| 覆盖采样 | 用户标点/命名位置、RSSI/连接/延迟/吞吐采样、平面图与热力图 | 点位由用户或验证定位提供，注明采样时间；不凭RSSI宣称精确距离 |
| 漫游与稳定性 | 当前AP变化、断线重连、信号趋势、延迟/丢包关联 | 只显示可观察事件，不能无数据推断漫游决策原因 |
| DNS | 系统指定网络解析、可配置解析器、记录类型、耗时/错误、IPv4/6、对照 | 区分系统/显式DNS和DoH/DoT，TTL/响应来源真实 |
| Ping与路由 | ICMP、适用TCP连通性、可支持的traceroute、逐跳/丢包/抖动 | TCP不冒充ICMP；无回应不等于目标下线，探测方式明确 |
| 端口与服务 | 单端口、用户指定范围、连接耗时、明确协议的服务检查 | 超时/拒绝/过滤分别记录，有界并发与取消 |
| Web/TLS | HTTP请求、重定向、DNS/连接/TLS/首字节/下载分阶段、证书链/有效期 | 结果和用时来自实际路径，不全局关闭证书验证 |
| 局域网发现 | mDNS/DNS-SD、SSDP/UPnP、用户范围内连通性、IP/名称/服务 | 设备与服务证据、去重/IPv6；不依赖读取受限ARP文件 |
| 局域网设备 | SSH/VNC/HTTP/SMB/MCP等可连接入口、WOL、已配置SNMP/路由器只读信息 | 发现不等于授权登录；改设备配置属于独立操作 |
| 测速 | 受控HTTP上下行、iperf3 TCP/UDP、并发/时长/方向、延迟/丢包/抖动 | 指定服务端与流量预算；丢包测量与抖动算法注明 |
| 持续监测 | 有界Ping/TCP/HTTP/DNS、设备在线、信号/速率趋势、阈值事件 | 每任务会话/停止/通知，调度与系统限流如实显示 |
| 数据包分析 | 显式导入PCAP/PCAPNG；可选本机VPN捕获；Root接口捕获 | 本地解析过滤、时间线/统计/导出，来源与捕获范围明确 |
| 近场/外设网络 | Wi-Fi Direct/Aware/RTT按硬件、BLE GATT、USB/以太网系统网络 | 支持探测与权限，不能仅因API存在就承诺外设兼容 |
| 网络报告 | 快照比较、诊断过程、可复制结论、JSON/CSV/图表和任务附件 | SSID/MAC/IP/域名/载荷可审阅脱敏，模型只依据真实测量 |

能力初期重点为网络总览、Wi-Fi扫描/信道图、DNS/Ping/TCP/HTTP；局域网发现、测速和持续监测紧随P3，不能全部拖到末期。RTT、新Wi-Fi字段和抓包属于高级包，但保留正常入口及明确准备方式。

### 19.3 Wi-Fi权限 新旧版本与测量边界

WifiManager扫描、WifiInfo、ConnectivityManager和NSD为主；使用当前Network回调获取连接信息，字段按SDK/权限删改判断。NEARBY_WIFI_DEVICES不能代替所有扫描所需精确位置权限，位置开关及ACCESS_FINE_LOCATION依具体API请求；说明用于附近网络分析，不因扫描授权顺便记录地理轨迹。

系统扫描有配额，优先复用实际扫描完成广播与缓存，显示采样时间、刷新失败/限流和下次可请求状态。RSSI连接监测与主动周边扫描分开调度，不把绘图刷新当每秒新射频采样。基础使用不要求用户关闭Wi-Fi扫描节流或开启开发者设置。

新设备/系统支持时展示6GHz、320MHz、MLO等实际字段；老设备保留现有频段，不按系统版本伪造硬件支持。RTT必须同时满足手机、AP和权限/可用性要求；RSSI估距只能标为估计，不能替代RTT。普通AP扫描也不是频谱仪、monitor mode或原始802.11帧捕获。

2026-10-18对三星只读查询，系统声明Wi-Fi、Aware、Direct、Passpoint、RTT、BLE和USB Host；未执行周边扫描、测距或外设连接。模拟器负责权限和接口行为，Wi-Fi图表仅可用明确合成样例做UI测试，不能作为真实无线性能证明。

依据：[Wi-Fi扫描](https://developer.android.com/develop/connectivity/wifi/wifi-scan) · [附近Wi-Fi权限](https://developer.android.com/develop/connectivity/wifi/wifi-permissions) · [WifiInfo](https://developer.android.com/reference/android/net/wifi/WifiInfo) · [RTT](https://developer.android.com/develop/connectivity/wifi/wifi-rtt)

### 19.4 原生网络 发现和配置

显式绑定可用Network做可复现诊断，记录Wi-Fi/蜂窝/VPN实际路径，不自动关闭用户VPN或切系统默认网络。DnsResolver/Network解析与受控DNS客户端互相校验；ConnectivityDiagnosticsManager的可见范围受应用角色/网络归属限制，不能当成任意系统网络故障全量日志。

NSD/mDNS与SSDP发现采用有界窗口，必要多播锁按会话释放。设备IP、名称、MAC/OUI只显示有依据且可用的字段，MAC随机化和系统限制下不推断绝对身份。已发现设备列表不等于完整拓扑；交换机端口/AP关联需要经配置的管理接口读回。

Wi-Fi连接/建议/本地设备组网通过正式Specifier/Suggestion和用户系统授权路径，区分仅App网络与系统默认网络。不假定普通APK可任意开关Wi-Fi、编辑系统路由或读取已保存密码。配置变更、WOL和路由器写入显示目标和影响，按任务授权执行并读回，不将分析工具默认为自动改全网。

依据：[Network](https://developer.android.com/reference/android/net/Network) · [DnsResolver](https://developer.android.com/reference/android/net/DnsResolver) · [网络诊断API](https://developer.android.com/reference/android/net/ConnectivityDiagnosticsManager) · [网络Specifier](https://developer.android.com/reference/android/net/wifi/WifiNetworkSpecifier) · [LAN权限](https://developer.android.com/privacy-and-security/local-network-permission) · [Android10网络隐私变化](https://developer.android.com/about/versions/10/privacy/changes)

### 19.5 组件复用与抓包

参考[WiFiAnalyzer](https://github.com/VREMSoftwareDevelopment/WiFiAnalyzer)的扫描、信道、筛选和展示设计；该项目GPLv3，复制代码前核对与Floe分发的兼容路线，不能直接当无条件可嵌入SDK。[iperf3](https://github.com/esnet/iperf)作为受控测速候选，固定源码/ABI与工具协议，不依赖未知公共测速服务器。

[PCAPdroid](https://github.com/emanuele-f/PCAPdroid)作为无Root捕获/分析参考，许可证、原生传递依赖和功能边界逐项核对。普通VpnService捕获需要系统同意并占用当前用户/资料的VPN位置，可能与已有VPN互斥；启用前说明冲突，不静默替换现有网络路径。VPN捕获看到的是经过自身隧道处理的流量，不自动解密TLS，也不等于AP级无线监听。

优先提供文件导入分析和Floe自身网络诊断，VPN捕获可选；GitHub Root路径可通过明确接口/过滤规则捕获以避免强占VPN，但需要真实权限、内核和工具支持。抓包有范围/过滤器、时间/大小上限、停止与文件轮转；PCAP含敏感内容，分享和上传需明确选择。Play网络功能保留，VpnService若采用则单独核对其用途声明和政策资格；不能因移除手机操作模块就假定VPN用途自动通过。[VpnService](https://developer.android.com/develop/connectivity/vpn)

### 19.6 Agent工具与测试

原生工作台和Agent走同一网络服务，结果结构包含method/source/network/target/status/observations/limitations。按能力发现具体网络动作，不能给一个万能工具接收任意宿主命令。普通已授权范围不反复确认；扫描目标/网络改变、长期监测、流量和设备配置的范围进入任务契约。未经请求不在本轮主动扫网或测速。

三星真实网络测试：权限同意/拒绝/撤销、定位开关、扫描限流和缓存、Wi-Fi切换/VPN、IPv4/IPv6、DNS/端口、已配置服务端测速、断线/取消。最新AVD测试target37权限和新API，合成无线数据明确标注；6GHz/MLO、RTT、USB网卡和不同AP由具备硬件的用户反馈补齐，不据此关闭已有正常功能。

核心验收链：选择网络 → 查看Wi-Fi/地址 → 测DNS/网关/目标端口 → 发现服务 → 可选测速/监测 → Agent结合证据解释 → 保存脱敏报告。复杂现场链再联动已配置SSH/路由器只读诊断。缺响应、无权限、服务不支持和硬件缺失分别报告。

## 20 GitHub Root 增强与桌面式系统操作

### 20.1 开关与授权

GitHub full内置默认关闭的Root增强设置。用户选择启用后才启动Root管理器授权和有效UID/功能探测；存在su路径、ADB shell可用或开机标记都不能证明App已获Root。支持未安装Root、拒绝、临时允许、永久允许、超时、撤销和Root后端失败等状态，关闭/撤销后普通功能继续工作。

采用[topjohnwu/libsu](https://github.com/topjohnwu/libsu)作为优先候选（Apache-2.0），复用shell管理、IO与RootService IPC；固定版本并验证实际Root管理器。[Magisk su说明](https://topjohnwu.github.io/Magisk/tools.html)用于核对授权/工具行为，不把某个管理器专有接口写成所有Root设备都支持。

不提供自动Root、bootloader解锁或安装Root管理器流程。本计划只针对用户已经Root并主动授权的设备；不会改动当前三星的系统/启动链，也不因增加计划而弹出su授权。

用户于2026-10-18追加直接要求：非Root设备可通过ADB获得更大权限，该能力**仅GitHub/full版提供**。自本节起能力分为三档并分别验收：**普通档**（默认安装即得，SAF/Accessibility/分享等正常用户授权路径）；**ADB-shell档**（用户在设备上明确选择并完成官方配对/授权流程后由用户发起的受控通道，不等于Root，不随重启自动激活，缺失时仅相关操作不可用）；**Root档**（仅full、默认关闭、需既有Root与用户授权）。实现归G08，真机验证归G12、新系统/平板验证归G13，产物与feed打包归G15；Play变体物理排除该模式的客户端/内嵌组件/特权服务/UI/依赖/Manifest条目/DEX与assets，不作为普通功能前置。能力边界、可选实现路线与生命周期详见[ADB 增强调研](FLOE_ANDROID_ADB_PRIVILEGE_RESEARCH.zh-CN.md)（2026-10-18 已完成源码与文档审查，设备未实测）；本计划不把源码可行性当作发行 App 的运行证明。Main 采纳优先复用外部 Shizuku 管理器与 MIT 客户端 API 的方向，内嵌配对客户端作为后续备选，仍须完成协议、密钥和环回权限验证。持久一次性授权与活体 shell 服务分开复核，Floe 进程重启、管理器死亡和设备重启分别设计恢复；停用只终止 Floe 自有服务。AVF 的权限定义已跨版本定位，但资源包/权限、系统特性、硬件、客户端调用和实际 VM 创建分别验收，不改变 G03 的 PRoot 基线。第17.5节“不用开发机ADB替身证明普通模式验收”的规则继续有效，但不禁止用户明确启用的发行版ADB-shell档自身按G08/G12/G13验收；ADB root、模拟器shell或开发机授权都不等于Floe已获得该档能力。

### 20.2 功能范围

| 域 | 无Root完整路径 | GitHub Root增量 |
| --- | --- | --- |
| 文件工作台 | 私有项目、长期SAF、适用所有文件、MediaStore、网络Provider | 用户明确授权的额外路径、系统元数据/所有权与真实可写区域 |
| 网络诊断 | Wi-Fi分析、NSD、socket/DNS/测速、可选VPN | 实际可用接口/路由/邻居/连接表、原始探测、受控tcpdump等 |
| 进程/服务 | Floe自有任务/服务与正式可见信息 | 更完整进程/系统服务查看、明确目标停止/重启和读回 |
| 应用管理 | 公开包信息、系统安装/卸载界面和正式Intent | 经授权的软件包管理、指定应用/服务操作和状态检查 |
| 手机操作 | 用户启用的AccessibilityService | 经验证的系统输入/显示与设备适配能力，不保证突破安全窗口 |
| 系统维护 | 系统设置入口、可获得诊断、应用缓存清理 | 按指定范围文件/服务/设置管理，有状态快照和恢复方案 |

Root不是所有能力的统一通行证：内核、驱动、SELinux、只读分区、硬件、App授权和加密状态可能继续限制。Wi-Fi频谱/监听、硬件虚拟化、系统分区写入和特定应用数据不能仅因UID0就宣称可用。每项必须探测并给出真实状态。

### 20.3 服务和操作契约

Root模块位于独立`:root-system`，通过有身份校验的专用服务向普通App提供有界文件、进程、网络和系统动作。验证调用App/会话身份，Root会话绑定taskID/runID、执行目标、作用范围、时限、取消和审计，不暴露未经校验的导出组件或无认证本地端口。

普通脚本与包命令继续通过已有Linux环境exec.shell；不得因为开了Root便把所有模型代码改在Android宿主执行。系统管理使用显式Root后端和受控操作协议，记录当前实际主机、权限与路径；需要扩展宿主命令能力时单独更新正式契约，不恢复已移除的语言执行别名或隐式提权。用户手动Root终端也要清楚显示宿主身份，不能与Linux/SSH标签混淆。

用户对Root开关和管理器授权不是对任意目标写入的无限同意。任务范围内常规已授权步骤不逐次重复弹窗；扩大到新路径/系统目标、破坏性覆盖、网络/权限或启动项变化按实际后果取得授权。网页、文件、其他App屏幕和工具输出仍是不可信数据，不能授予Root。

修改遵循读取当前状态 → 明确目标与恢复点 → 执行 → 读回；只返回退出码0不足以证明成功。Root任务有真实输出背压、超时、子进程/进程组与中断收敛，避免只杀su客户端留下Root进程。关闭模式时停止归属工作或明确有界排空、释放IPC/句柄；不能在用户关闭后暗留后台daemon。

默认不改SELinux全局状态、不挂载系统分区可写、不写boot/init、不读取或外发其他应用凭据。若用户明确请求具体系统维护，按对应任务和可恢复后果执行；开机自启/常驻Root服务若提供，作为独立可见选项并可撤销，不默认安装启动脚本。

### 20.4 构建与测试

play构建不含Root实现、libsu专属依赖、Root服务/资源、菜单、模型工具和Root宣传；普通网络/文件能力保留。禁止通过下载模块或伴侣App给Play恢复Root模式。full版Root开关关闭、缺Root和授权失败都是完整验收路径。

测试采用无Root三星验证回退，AOSP/userdebug Root可用的模拟器验证受控系统操作与服务；ADB root不等于普通App经Magisk获得su，Root管理器授权/撤销和厂商内核差异以有条件的测试设备或用户自愿反馈补验。不Root三星，不拿模拟器替代真实无线、Root管理器和只读系统验证。

已实现且基本验证可用的Root能力向符合条件的GitHub用户开放；缺特定Root真机体验记入兼容报告，不把整个模式锁在开发菜单。故障需有停止/撤销和恢复路径，反馈不默认上传系统文件或其他App数据。

## 21 无 Root 文件工作台与长期授权

### 21.1 授权一次 持续使用

非Root为主路径，不是功能残缺的演示模式。首次进入用户选定目录使用ACTION_OPEN_DOCUMENT_TREE，获得实际读写授权后调用takePersistableUriPermission并保存tree URI、提供方、权限标志和用户名称；浏览、再次启动和正常升级时复用，不每个文件/每次运行重弹选择器。

权限具有范围与寿命：被撤销、提供方移除/更换、目录移动、存储卷断开、应用卸载或系统恢复等可能使其失效。启动/访问时轻量检查，实际失效才请求重新关联，保留文档身份和未提交草稿。一次根项目授权覆盖提供方允许的子树，但不扩大到无关目录或其他App私有区。

Android11+的SAF对主存储根、部分存储卷根、Download目录树、Android/data与Android/obb等存在具体限制。不能概括成“除了Root目录都能点一次授权”。单文件选择/系统打开可能提供与tree不同的范围，按实际提供方能力处理。[SAF官方限制与持久授权](https://developer.android.com/training/data-storage/shared/documents-files)

### 21.2 文件来源与操作

| 来源 | 访问实现 | 用户可用操作 |
| --- | --- | --- |
| Floe私有项目 | 自有文件系统 | 完整文件树、创建/编辑/重命名/复制/移动/删除/搜索/压缩/导出 |
| 授权目录树 | SAF/DocumentFile/ContentResolver或受控Provider适配 | 在提供方实际支持范围内完成同一操作集，显示只读/不支持动作 |

| SD卡/OTG | SAF或适用所有文件/驱动路径 | 读写与批量管理，拔盘后保留恢复状态，不自动删除资料 |
| 云盘/网络Provider | SAF或已有SMB/WebDAV/SFTP等协议 | 列表/下载/写回/冲突恢复，离线和能力差异准确显示 |
| Git仓库/Linux环境 | 明确本地工作副本和映射服务 | 索引、编辑、Git、构建/运行、回写并核对来源修订 |

完整操作集还包括收藏/最近目录、多选、排序筛选、全文/名称检索、文件详情、分享/打开方式、恢复副本和任务成果定位。批量删除/覆盖和跨提供方移动先保留所需恢复策略，移动在源删前验证目标成功；空间不足、权限撤销、半完成操作分别恢复，不静默丢文件。

SAF URI不是本机路径，也不保证随机写入、监测或原子重命名。IDE/LSP/Office/Linux需要本地文件时使用明确缓存/工作副本，版本/摘要关联原URI，保存后重新核对并提交；不是每次打开都另存无法追踪的副本。不支持热监测的提供方采用有界刷新与冲突检测。

### 21.3 所有文件访问与渠道

为以多目录文件管理为核心需求的用户提供显式所有文件访问设置入口，授权后检查Environment.isExternalStorageManager并启用更便利的共享存储路径。它是系统特殊访问设置，不是普通一次runtime对话框；用户拒绝/撤销后保留SAF和项目功能。

MANAGE_EXTERNAL_STORAGE可扩大共享存储/适用SD与OTG访问，但不等于Root，仍不能任意读取其他App私有目录；通过SAF访问时也不自动绕过SAF的限制。GitHub版可以按实际需要请求；Play版按真实文件/文档管理核心用途核对资格并申报，不预设批准，也不伪装用途。若该渠道无法获得资格，保留可用目录授权与文件管理，不削掉整个工作台。

依据：[所有文件访问范围](https://developer.android.com/training/data-storage/manage-all-files) · [Google Play用途资格](https://support.google.com/googleplay/android-developer/answer/10467955?hl=en)

### 21.4 低打扰授权体验与验收

建立统一“已授权位置”管理，显示可读写状态、关联项目、来源和撤销操作。任务需要新增位置时弹系统选择/授权并回到原任务；保存授权后不重复询问已覆盖步骤。目录权限只解决访问，不自动批准外发、不可恢复删除或所有未来Root操作。

三星与最新AVD分别测试：选择一次 → 新建/编辑/重命名/移动/删除 → 关闭重开 → 设备重启 → APK升级仍可访问；再测撤销、断盘、只读Provider、换文件路径、权限重关联和多项目。使用实际用户授权流程，不用ADB appops授权替代验收。

正常向用户开放所有已实现文件操作、网络和开发入口，遇到真正系统边界才说明具体限制与替代路径。用户认为普通目录应可操作的场景优先形成样例反馈和修复，不因“安卓可能有限制”提前把文件工作台做小。


## 22 与 iOS 保持一致的界面与美术

### 22.1 视觉目标与优先顺序

安卓App内视觉尽量与当前Floe iOS一致：相同品牌、页面结构、主次层级、功能位置、组件样式、布局密度和状态反馈，让用户切换系统时仍然觉得是同一个产品。采用Compose或其他原生组件是实现选择，不是另起Material视觉方案的理由。

优先顺序为当前已确认的iOS实际界面 → 对应源码/语义token与资源 → 已记录且仍有效的设计约定。旧截图、宣传图、历史PRODUCT/DESIGN说明只能作线索，与当前实现冲突时先核对，不能据其重设计iOS或复活已变更的交互。

参考源码包括 `FloeAgent/FloeApp/Design/FloeTheme.swift`：已有青/蓝/紫品牌渐变，选择/主操作强调；琥珀待处理、红色失败/破坏性、绿色确认成功；内容阅读面不透明，材质主要用于导航/输入等chrome。移植这些语义和当前画面，不把每页改成密集卡片/大色块。

不承诺系统权限弹窗、输入法、通知栏和系统字体渲染逐像素相同；这些由系统负责。App控制的区域优先尽量一致，确有API、性能、硬件或可访问性原因的差异局部登记，不据此把整页视觉改掉。

建立FloeAndroidTheme与对应token/公共组件，统一颜色、排版、尺寸、间距、圆角、分隔、材质、动效、状态图标和触控区域。对可共享的设计值采用可追溯映射/生成，不同时维护两套随意漂移的常量；不为此改动无关iOS代码。

Sora、Termux终端组件、Office内核、PDF/Ink、媒体和CAD等主要复用底层能力。其外层工具栏、标签、空态、加载/错误、面板和命令入口由Floe统一包装，不能将各组件示例App原样拼接。文档内排版、代码和终端配色也要与对应iOS样例对照；引擎不支持的主题边界明示为局部差异。

安卓新增网络工作台、设备操作、长期目录授权和Root设置采用现有Floe的列表/检查器/图表/工具卡风格。不要因这些是安卓独有功能便建立另一个管理后台视觉；也不要为了对齐iOS删掉安卓应有能力。

### 22.4 交互与状态对齐

同时对齐加载、空态、失败、待授权、运行、停止中、未知结果、只读、冲突、选择、多选和恢复状态。只比静态首页无法验收：流式消息、工具展开、键盘弹起、横竖屏和编辑器全屏切换均使用对应状态样例。

iOS与安卓的相同动作尽量保持同样入口和反馈。Android系统返回/预测返回先关闭临时层或编辑状态，再按已有任务生命周期导航；返回预览不提前删除草稿。长按、右键、键盘和触控笔是并列输入路径，不能只复制触摸外观却丢掉可用交互。

系统权限、分享选择器、文件选择器和通知使用真实安卓界面，并在进入/返回时维持Floe上下文。不以自绘iOS弹窗冒充系统授权；适用的新系统原生特性继续采用，而不因视觉对齐关闭它们。

### 22.5 手机 平板与新旧系统验收

固定同一内容和状态，iOS参考截图与Android截图成对保存。最新ARM64平板AVD对照iPad多栏，三星对照iPhone紧凑布局；对不同宽高比使用内容区/组件对照，不只对整张图粗略缩放。

4. 目标关闭前保留对应参考与Android实际画面，核对主要视觉及基本输入/返回/键盘行为；纯组件演示或占位壳不代表功能页面通过。

组件库升级或替换集中在设计系统适配层处理。后续目标的交接必须携带本节和`FloeAndroid/planning/UI_FOUNDATION.md`；大体视觉和主要组件不作为G14欠账。

## 23 目标模式执行顺序：先代码完整 再集中调试

### 23.1 本轮决定与目标使用规则

用户要求先看合理的阶段目标，确认后再使用目标模式，一次完成一个小目标再切换下一目标。本节是实际执行顺序；第11节的85个工作包继续作为范围和验收台账，不丢弃其完成标准。当前状态为**用户已于2026-10-18确认计划；G01与G02代码阶段完成交接并关闭，下一活动目标为G03，其余目标依序待开始**。

采用四个大阶段、15个小目标。第一阶段的G01–G11完成全部约定功能的代码，包括按当前iOS页面对齐的完整界面、真实后端、平台适配、异常与恢复路径；对应目标进行必要编译、定向检查及关键内核最小运行验证。第二阶段G12/G13集中做跨模块和设备端到端联调；第三阶段G14集中复核视觉细节、性能和体验；第四阶段G15整理测试候选与反馈闭环。发现真实缺陷时在对应阶段修复，不把“先写代码”理解成禁止运行或推迟架构、布局和组件选型。

用户同意这套范围后，一次只创建一个活动目标，写明输入、修改范围、交付物、退出条件和依赖；完成并核对产物后关闭，再创建下一个目标，不并行堆积多个活动目标，也不反复申请已同意范围的实施许可。每完成一个目标向用户简报成果、验证结果、未覆盖边界和下个目标；遇到阻碍报告具体依赖，不能把缺实现、编译失败或未完成工作标成完成。新出现且实质改变范围的平台限制单列处理。

每个目标内部仍按功能切成更小的提交/检查单元；无需一次性耗尽整段对话。结束时留下源码版本、差异、接口、命令、实际结果和下一步，后续从交接继续。目标模式不是不经授权公开发行或新增敏感账户访问的许可。

#### 23.1.2 G02 执行效率与验证顺序（2026-10-19）

- **按需派发，不预填 Worker 队列（用户纠偏，2026-10-21）：** 后续功能要求保留在计划中；当前任务交付后，先对照实际源码和范围减去已覆盖部分，再决定下一份必要工作。只有输入已具备、容量可用且写入边界已明确的任务才派发。依赖未就绪或职责重叠的工作不提前排队；可合并的目标/Home/任务生命周期等收口到一个连贯交接，避免重复派发。并行数依据实际容量与资源确定，不以塞满队列作为进展。 每次派发前核对实时运行/排队状态、前序交付和当前已合并源码；后序输入必须来自已核对的交付，不能继续沿用过期基线。相同文件或资源串行归属，集成按前像校验并保留新增修改，禁止整目录覆盖。已完成包先收取并由主负责人整合，不因名额释放立即补派；共享接线保留带前像的局部补丁，等现有文件所有者交回后合入。其他项目的任务不由本轮擅自取消。

- **优先打通依赖：** 运行时、模型/凭据、真实对话链路优先进入集成验证；独立源码任务并行推进。源码任务不能长期占满名额，让已具备输入的关键编译任务空等。按实测资源短时调整任务并发，重型编译、共用缓存与模拟器仍由同一资源锁串行管理；不改变模型路由或取消重做正在进行的任务。

- **减少重复工作：** 交接以已核对的源码、实际接口、失败记录和剩余步骤为准。稳定接口先交接，下游不重复通读历史；复用同一检出目录下有效的增量缓存和精确来源产物，只因源码变化、失败或未解决风险重跑受影响检查，不重复构建未变化的产物来整理报告。

#### 23.2.1 G06 手写笔与触摸防误触（2026-10-21追加）

Android已有原生手写笔事件；实际压感、悬停和掌触识别仍取决于设备、笔与驱动，不能从系统版本或蓝牙连接推定支持。采用“原生输入识别＋系统取消回滚＋应用交互回退”的分层方案，覆盖手记、PDF批注及画布；共用输入适配，不共用各编辑器的选择、撤销或助手状态。当前只补充调研和后续实施要求，G02-R2仍为唯一活动目标，不提前开始G06代码。

- **具备主动笔输入的设备：** 按实际工具类型区分笔、橡皮与手指，提供“仅笔书写”；手指导航与书写分离，笔书写期间抑制掌触引发的平移、缩放和误选。是否恢复双指导航、何时解除保护须有明确状态和可测试规则，不能仅过滤落墨却仍允许手掌移动页面。笔按钮、压感、倾角、悬停仅在有真实输入时启用。
- **系统识别后的补救：** `ACTION_CANCEL`终止当前整组手势的活动事务；API33及以上的`ACTION_POINTER_UP + FLAG_CANCELED`仅撤销指定指针。按稳定pointer ID管理临时笔迹与手势事务，取消后撤掉相应临时/预测呈现，防止误触残留进入笔迹、撤销记录、自动保存或导出；不误删此前已提交的无关笔迹。旧系统缺少完整取消信号时保留显式模式，不能承诺同等自动识别。
- **只有普通触摸的设备：** 提供明确的手指书写开关、画布导航/书写锁定与局部放大书写区；普通电容笔可能与手指无法区分，不承诺软件补出主动笔压感或可靠硬件掌托。接触面积、触点数量等启发式只作可关闭的辅助，不作为唯一判据，也不要求Accessibility或Root权限。
- **复用与代码门槛：** 本轮调研已完成并复核，采纳AndroidX Ink稳定版作为笔迹建模/渲染/笔刷/几何/序列化的优先路线；2026-10-21官方稳定版为1.0.0，Compose可用`ink-authoring-compose`接入，预测与前缓冲是按实际延迟结果采用的增强项。G06启动时复核版本并锁定依赖，逐工件确认minSDK、许可证、包体、ABI/16KiB和笔迹保存格式；评估官方记录的API29–32视图重新挂载等缺陷，必要修复按证据选择，不只按stable/alpha标签判断。渲染/预测库不自动等于完整防误触系统，也不等于IME手写转文字或OCR。补齐单/多指取消、pointer索引重排、笔与触摸交接、离开页面/锁屏中断、缩放坐标与保存重开的定向检查。
- **验证分工：** G12三星实测普通触摸、模式切换和中断恢复；G13平板模拟器验证事件/取消/布局逻辑，实体主动笔设备或用户自愿反馈验证真实掌托、压感、悬停与延迟。模拟事件通过不等于硬件体验通过；基本可用功能正常开放，反馈附设备、系统、笔型号和复现步骤，诊断不收集手写正文。

已核对的官方依据：[Android原生笔事件](https://developer.android.com/develop/ui/compose/touch-input/stylus-input/advanced-stylus-features)、[掌触取消与低版本限制](https://developer.android.com/develop/adaptive-apps/cookbook/stylus-palm-rejection)、[完整MotionEvent取消语义](https://developer.android.com/reference/android/view/MotionEvent#ACTION_CANCEL)、[Ink版本与已知修复](https://developer.android.com/jetpack/androidx/releases/ink)。本节是后续实现与验收计划，尚无触控笔设备通过结论；无主动笔也不意味着固件绝不会识别掌触，仍按实际取消事件处理。
