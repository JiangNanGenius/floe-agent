# Floe 3D 物理、动画与专业 CAE 预研发计划

日期：2026-11-07。

实施进度见[代码推进记录](FLOE_3D_SIMULATION_IMPLEMENTATION_STATUS.zh-CN.md)。

目标是在现有 3D 编辑器中形成完整的原生物理、动画和工程分析工作台。预研发先交付独立原生组件及可操作的 iPad 宿主，再将同一套组件接入现有编辑器，集中完成、统一交付。功能以真实输入、求解、显示、保存重开和导出为完成标准。

## 1 已确认的范围

| 决定 | 执行要求 |
| --- | --- |
| 使用目标 | 同时覆盖机械设计验证、动态场景与动画、专业 CAE 工作流。 |
| 计算位置 | 全部在 iPad 原生运行；本轮不采用 Linux guest、Web 求解器或远程服务器作为替代路线。 |
| 工程模型 | 实体、梁、壳、各向异性材料及铺层复合材料。 |
| 分析类型 | 静力、模态、线性屈曲、稳态与瞬态热、热应力、大变形、材料非线性、接触、流体、声学、低频电磁与高频射频。 |
| 流体范围 | 不可压缩和可压缩流、层流、RANS 湍流；首批湍流模型采用 SA 和 SST。 |
| 射频范围 | 全波频域、腔体模态、天线、端口、S 参数和辐射结果。 |
| 动画范围 | 刚体动画、骨骼与物理混合、布娃娃、次级运动、布料、绳索、软体、粒子与力场、缓存、烘焙和导出。 |
| 耦合范围 | 热应力、共轭传热、流固、结构声学四类明确的耦合流程。 |
| 验证方式 | 界面验证和代码层验证，复用已有有效证据，新增接入使用小型真实算例。全面数值资格重验证、大规模精度扫描、性能矩阵和物理设备试验不作为本轮门槛。 |
| 交付方式 | 工程上拆成可独立交接的组件包，最终在同一工作台统一交付。版本、签名和分发仍由现有主发布流程安排。 |

“全部覆盖”以上表明确列出的模型和工作流为边界。首轮声学采用线性声压模型；复材交付材料方向、铺层和分层结果；屈曲采用预载状态下的线性特征屈曲。后屈曲、裂纹扩展、复材渐进损伤、反应燃烧及任意多场组合不是这些条目的隐含能力。

## 3 原生组件与移植任务

| 组件 | 负责的能力 | 本轮必须完成的适配 |
| --- | --- | --- |
| Rapier | 实时刚体、碰撞、关节、驱动、绳索、布料、软体 | 静态 C ABI、Apple arm64 与 arm64 Simulator 分片、对象身份、受控步进、取消和缓存 |
| ozz-animation | 骨骼采样、混合、附加层、IK 与动作数据处理 | 接入 Floe 骨骼和权重模型，与物理驱动及现有时间线共用时钟 |
| Netgen 与现有 OCCT | 曲面与实体分析网格、区域边界及局部细化 | 无 GUI、无 Python 的库构建，保持 CAD 面与网格边界的映射，复用现有 OCCT |
| FEBio | 实体非线性、材料、接触和结构时间过程 | 作为库调用，补进度、取消、每任务文件目录、结果场提取及本地稀疏求解适配 |
| Chrono CPU FEA 与 modal | 梁、壳、铺层、机构柔性与模态 | 选择 CPU 子模块，接合实体与梁壳接口；提取质量与刚度矩阵供谱分析 |
| Eigen、Spectra 与 Accelerate | 共享线性代数、稀疏与特征值适配 | 完成约束消元、模态和预载几何刚度接口；线性屈曲需新增装配及结果解释 |
| MFEM | 热、声学、低频电磁和场离散 | 串行原生库、材料与边界转换、复数结果、场采样及后处理 |
| SU2 | 层流、SA/SST 湍流、可压缩流及共轭传热 | 去除运行时对命令行进程的依赖，封装迭代、网格与配置、取消和字段读取 |
| Palace 的电磁实现 | 射频端口、频扫、S 参数、腔体和天线后处理 | 复用算子、端口与后处理源码，映射到 MFEM 串行接口；不直接嵌入默认 MPI 可执行程序 |

以上为选定的预研发路线，尚不是已完成 iOS 移植的清单。R1 要先取得每项的真实对象编译、链接和最小调用证据；某个组件受阻时，记录具体符号、依赖或算法缺口及修复任务，其余独立组件继续。

Rapier 的官方 C 接口支持静态构建和双精度；ozz 提供采样、混合与 IK；Chrono 的 Reissner 壳有实际铺层接口。Palace 的标准构建依赖 MPI，串行嵌入属于本轮移植工作。[Rapier C 接口](https://rapier.rs/docs/user_guides/c/getting_started_c/)、[ozz-animation](https://guillaumeblanc.github.io/ozz-animation/)、[Chrono 铺层壳](https://api.chrono.projectchrono.org/classchrono_1_1fea_1_1_ch_element_shell_reissner4.html)、[Palace 构建依赖](https://awslabs.github.io/palace/stable/install/)。

所有组件从固定源码构建，记录版本、提交、补丁和哈希；逐项记录依赖闭包的许可证。Netgen、SU2 等 LGPL 组件补齐既有重新链接与源码提供材料。保留现有 OCCT 版本，统一 MFEM 和 Eigen 的依赖基线，避免同名库和全局状态冲突。

原生入口仅接受声明式物理和分析模型。C/C++ 异常在包装层转为错误；移除会终止 App、切换全局工作目录或启动子进程的调用；不在运行时引入 Python、MPI、CUDA、插件编译或脚本解释器。首轮求解以 CPU 和双精度为基础，Metal 承担现有视口与结果显示。

## 4 公共接口与数据流

新模块使用 FloeAgent/Modules/FloeSimulationKit，验证宿主使用 FloeAgent/Qualification/Simulation。模块内分为 Core、Geometry、Physics、Animation、Engineering、Fields、Storage 和 UI；这些子目录按职责组织，不为每个引擎再造一套项目和任务服务。

| 接口 | 输入与输出约定 |
| --- | --- |
| SimulationSourceRef | 项目、文档、修订、内容摘要和对象身份；绑定一次运行的不可变来源 |
| GeometrySnapshot | 由 CAD 宿主提供 B-rep 或显式网格快照、实例变换和稳定面/边标签；计算层不持有编辑器状态 |
| AnalysisMesh | 梁、壳、体单元与区域，边界选集、质量报告、几何映射和网格摘要 |
| PhysicalMaterial | 力学、热、流体、声学、电磁属性及单位、材料方向、铺层；与外观材质分别保存 |
| PhysicsScene 与 AnimationGraph | 物体、碰撞形体、关节、驱动、动画层、骨骼、柔体、力场、时间参数和随机种子 |
| SimulationStudy | 分析类型、材料分配、边界条件、载荷曲线、网格设置、耦合设置、求解预算与结果要求 |
| SimulationJob | start、progress、status、cancel、result；UI 和 AI 使用同一运行服务与身份检查 |
| ResultDataset | 点、单元、积分点及向量/张量/复数场，时间或频率轴、单位、来源摘要与求解器版本 |

数据流固定为：宿主捕获几何 → 建立模型和选集 → 网格或碰撞表示 → 原生计算 → 结果数据集 → 同一视口与导出器。显示网格、碰撞形体和分析网格分别持有自己的精度与映射。

### 几何和单位

- 实体选择体区域；壳由选面、厚度、法向和局部材料方向定义；梁由曲线、截面和方向定义；CFD 支持创建内部或外部流域及入口、出口、壁面。
- 网格检查闭合性、方向、退化单元、正 Jacobian 和边界标签。几何修复生成明确的新修订；面标签丢失或歧义时要求重新绑定。
- 保留既有 mm、N、MPa 和摄氏度合同，在原生后端边界集中转换；绝对温度、密度、转动惯量、热流和电磁量分别定义转换。摄像机与渲染尺度不参与工程单位推断。
- 材料按区域和铺层分配。强度判据只使用用户提供或有来源的强度数据；外观颜色不自动成为工程材料。

### 任务和持久化

- 服务持有任务，视图只观察。复用已有项目、工作目录、授权和取消链，计算回调不直接修改界面或当前文档。
- 一个 App 同时运行一个重型 CAE 任务，其余排队；原生库有全局状态时串行访问。求解前估算资源，超限返回可操作的提示，精度设置保持可见。
- 修改来源或配置生成新修订，旧结果保持可查看并标记过期；迟到回调不能安装到新修订。取消请求和工作线程实际结束分别报告。
- 新版分析包采用清单与分块字段数据，保存前验证、原子替换并记录校验和。旧 floeanalysis、球代理缓存和骨骼动画继续按原格式读取；显式保存新版时才写入新格式。
- 后台或锁屏按系统允许的运行时间推进，在安全边界保存检查点；恢复后继续或明确重启当前求解阶段。临时播放状态和求解缓存不覆盖 CAD 几何权威。

| 碰撞表示 | 查看并选择基本体、凸包、组合凸体和静态曲面碰撞表示 | 与实际采用的碰撞表示一致的预览、缓存与诊断 |
| 骨骼动画物理 | 编辑 FK/IK、动画层和骨骼物理模式；控制布娃娃、驱动强度及次级运动 | 连续且可缓存的骨骼姿态，镜头、物体和形变同步 |
| 布料绳索软体 | 选择固定点、碰撞对象、刚度、阻尼和风场；设置模拟网格与显示蒙皮 | 实际变形、碰撞和逐帧顶点缓存 |
| 粒子与力场 | 设置发射范围、速度、寿命、种子、重力、阻力及碰撞 | 可重复求解和烘焙的粒子运动；CFD 场另以结果动画播放 |
| 结构静力 | 在自己的实体和装配上分配材料、力、压力、重力、支撑和连接 | 位移、应变、应力、反力和求解状态 |
| 梁壳复材 | 定义截面、壳厚、材料方向和各层厚度/角度/材料 | 截面与分层应力、应变和位移；强度数据齐备时输出约定判据 |
| 模态与屈曲 | 选择约束、质量、模态阶数和保守预载 | 固有频率、振型、屈曲载荷系数与模态，不将模态因子当作实际变形量 |
| 非线性与接触 | 配置大变形、J2 塑性或超弹性、接触、摩擦及载荷步 | 载荷步收敛、变形、塑性或接触结果和失败步信息 |
| 热 | 设置导热、热源、温度、热流、对流边界和时间过程 | 温度、热流、时间历程和热平衡数据 |
| CFD | 设置流域、介质、入口/出口、壁面、层流/湍流和可压缩选项 | 压力、速度、温度、流线、壁面和整体力结果 |
| 声学 | 定义声学区域、介质、边界、激励与频率 | 声压、频响、声腔模态及结构声学结果 |
| 低频电磁 | 配置电势、电流、线圈、材料和边界 | 电势、电流密度、电磁场及谐波涡流结果 |
| 高频射频 | 定义导体/介质、端口、激励、频扫与辐射区域 | 复数场、端口量、S 参数、腔体模态和天线方向图 |
| 四类耦合 | 为参与模型选择接口、时间或频率、交换变量及收敛条件 | 热应力、流固和结构声学的关联结果，共轭传热的温度/通量结果与耦合状态 |

实时物理动画和工程 FEA 分别输出自己的结果。碰撞冲量不能直接充当工程应力云图；复材物理预览也不能代替其结构分析。

## 6 动画求值与出片

统一时钟依次完成：关键帧与动画层采样 → IK/FK 目标 → 运动学碰撞体与物理驱动 → 固定步长物理求解 → 骨骼姿态及柔体蒙皮 → 相机与视口输出。每个对象或骨骼明确属于关键帧控制、动力学或物理驱动模式；混合权重用于明确的层或驱动规则，避免两套系统同时写同一个姿态。

现有 physicsCacheID、rigID 与普通 tracks 的互斥限制通过新版动画图和兼容适配解除。相机轨道可与骨骼和物理同时存在；骨骼局部/世界变换、Morph 和柔体显示映射有固定求值顺序。

模拟步长与视频帧率分离，均写入运行记录。跳帧从最近检查点恢复并向前求解，倒放读取已有缓存；预览、帧抓取和导出使用同一采样接口。修改几何、驱动、材料、种子或时间参数后，相关缓存失效。

刚体和骨骼可烘焙成动画轨道并按支持范围导出 GLB。布料和软体保存顶点缓存，接通视频与序列帧；变拓扑结果记录逐帧拓扑。动画资产导出单独验证轨道、skin 和 Morph，不从静态 GLB 导出器推断支持。复用现有视频服务处理帧率、尺寸、进度、取消和最终文件验证。

## 7 原生工作台与 AI 操作

工作台使用“建模、动画、仿真、分析”四种工作模式，复用已有外层导航与中央 Metal 视口。iPad 左侧为对象和研究列表，右侧为按当前步骤展开的设置，底部为可收起的时间线、曲线和任务状态；iPhone 使用同一流程的分步面板。

分析操作顺序为：选择几何 → 创建研究 → 材料与连接 → 载荷和边界 → 网格 → 求解 → 结果。动画操作顺序为：对象/骨骼 → 轨道与驱动 → 碰撞和柔体 → 预览 → 缓存 → 烘焙/导出。

结果界面提供云图、变形倍率、剖切、探针、向量/流线、时间和频率选择、曲线及对比。复材提供铺层表与分层结果；射频提供端口、S 参数与方向图。一般界面显示实际进度、可执行操作和简短错误，算法标识与详细诊断放入详情，中英文同步。

AI 在现有 CAD/Studio 发现与授权链中使用同一套读写、配置、网格、运行、状态、取消、烘焙、结果查询和导出操作。返回真实任务 ID、来源修订和产物引用；大字段分页或按区域读取，截图沿用既有受控图像产物路径。实际使用的参数需要从编辑器一路传到原生后端，再进入保存与导出记录。

| R7 编辑器集成 | 将同一组件接入现有 3D 编辑器、工作室和 AI；统一项目、文档、结果与导出 | 实际 App 中能完成各类操作，旧档案兼容，字段与版本归属正确 |
| R8 统一收口 | 运行受影响代码检查和界面流程，修复失败，整理产物与交接 | 完成功能清单、原始失败和修复证据、精确原生产物、App 截图、未完成项及清理记录 |

依赖按能力推进：R3 使用已交接的 Rapier/ozz 和必要数据合同即可开始；R4 需要分析网格与结构后端；R5 按对应场后端和网格就绪情况开始；R6 使用已完成的单场服务；R7 按验证后的短交接集成。无需等待所有 R1 后端完成才推进已就绪模块。用户可在预研发宿主查看进展，统一交付以 R7/R8 的实际 App 功能清单为准。

### 执行分工

- 主协调：公共合同、依赖与许可证判断、共享文件接合、最终界面判断、App 构建与验收。
- A 包：原生物理和动画；分为后端、动画混合、缓存/出片三个独立交接，不将整个流程累积在一个长期 worker 会话。
- B 包：几何、网格和结构分析；分别交接网格桥、结构服务、梁壳/谱分析和热服务。
- C 包：CFD、声学与电磁；分别交接原生后端、研究配置/结果和耦合适配。

每次只给 worker 一个完整且可独立验收的结果包。共享 Package.swift、project.yml、生成工程和现有工作台文件由主协调串行接合；当前制造与 CAD 文件先由其现有负责人交接。沿用 main，共享资源用同一个锁名，只有明确的冲突隔离需求才使用临时工作树。

## 9 界面与代码层验收

验证遵循用户选择：复用已有组件证据，新增接口和算法适配保留必要的对象编译、相关测试与小型真实求解；不启动完整商业 CAE 资格矩阵。每项功能仍需实际调用其原生后端，并检查结果、状态和保存回读。

R0 为每个小算例记录输入、预期物理量、参考来源和允许误差；已有算例沿用有效断言。代码检查同时验证边界条件实际生效、残差与守恒量、字段位置及单位，结果导出后再次读取并比较。动画在同一固定构建和步进设置下检查种子、跳帧及缓存一致性；跨平台浮点结果采用约定误差。

| 场景 | 代码检查 | 界面与产物检查 |
| --- | --- | --- |
| 刚体和机构 | 碰撞、旋转、质量/惯量、驱动与约束参数实际生效 | 门铰链、马达与碰撞物体可运行，曲线和运动一致 |
| 动画混合 | 关键帧/IK/物理的求值顺序、局部/世界变换、种子与检查点 | 骨骼物理、布料和相机同播；跳帧、倒放、烘焙与导出一致 |
| 真实 CAD 模型 | 几何修订、面选集、区域和网格映射 | 现场建立带孔支架，设置载荷并分析，改变来源后正确提示过期 |
| 结构与热 | 利用已有 patch、悬臂和导热小算例，检查残差、反力及单位 | 云图数值、变形倍率、探针与导出字段一致 |
| 梁壳复材 | 材料方向和铺层进入单元，刚度/质量/几何刚度及特征值合同 | 改变铺层角度能得到对应结果，振型与屈曲结果可重开 |
| 非线性接触 | 载荷步、塑性/超弹性、接触与不收敛状态 | 显示真实结果与失败步，保留当前设置及已完成结果 |
| 流体 | 小管道和喷管案例，覆盖质量/能量变量、边界、SA/SST 和可压缩配置 | 流域设置、流线、压力和整体力可查看导出 |
| 声学与射频 | 声腔、线圈、电容、同轴端口和天线的小型上游算例 | 频率、复数场、S 参数与方向图的数据对应正确 |
| 耦合 | 检查量纲、界面方向、载荷转移、时间同步及收敛返回 | 四类耦合研究的设置、结果和来源关联完整 |
| 生命周期 | 取消、资源超限、几何失效、归档损坏、旧版本、迟到结果和原子保存 | 状态真实、错误可处理、重开后可继续，失败保留可恢复资料 |
| AI 调用 | 工具发现、修订围栏、配置/运行/查询/取消/导出与实际字段一致 | 通过已有模型配置调用同一服务，收到真实结果和可查看产物 |

新增原生库必须完成 arm64 iphoneos 与 arm64 iOS Simulator 的对象/链接编译；Swift 并发改动需要真实 SIL/对象编译。原生数学宿主运行用于代码层证据，正式 App 仍需在仓库指定的复用 iPad 模拟器中验证实际入口。模拟器和 App 构建串行，不创建或抹除设备，不使用用户物理 iPhone，不将物理设备验收加回本轮门槛。

源码、工具链、目标、实际命令、结果和截图随交接保存。每次构建后导出必要库、符号及失败记录，清理本任务已无用途的可再生输出。功能通过、数值全面资格与真机性能分别表述。

## 10 第一批可直接下发的工作

1. 主协调先完成 R0：固定 Core 与宿主几何接口、单位/字段合同、动画求值顺序、取消和档案版本，建立上述功能清单及小算例清单。
