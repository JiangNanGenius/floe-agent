Two follow-up items were identified in this first sources run and are fixed
in the committed scripts (the run below reuses this image artifact, so no
image byte is rebuilt):

1. the Ubuntu cross-toolchain source resolution parsed
   `Source: gcc-defaults (1.214ubuntu1)` into a broken package name, so the
   `toolchain-source/` glibc/cross source was not fetched — the resolver now
   reads the owning packages of `riscv64-linux-gnu-gcc`, `libc.a` and
   `libgcc.a` and strips the version suffix;
2. the runner relink object (`floe-exec-riscv64.o`) did not travel with the
   image job's evidence (the copy was added after the run), so a sources
   retry now compiles it from the same sources/flags when it is absent.

## What this does and does not qualify

- **Does**: the image boots as a real guest under the pinned engine with the
  runner as PID1; the guest clock comes from `floe.epoch`; signed HTTPS APT
  works with the packaged userland; the 13 user commands are present and 11 of
  them performed real work; the artifact digests, manifest and evidence are
  recorded.
- **Does not**: prove iPad/device performance, interactive sessions, remote
  SSH/SCP transfers, or that the guest is a complete Linux. The manifest is
  written with `qualified: true` (the run above passed) but
  `provenance.distributionAllowed: false`, so the app's official download
  entry still refuses to offer it. Public distribution additionally needs the
  corresponding-source offer published at a stable URL and the archive digest
  pinned in `LinuxGuestImageDistributionCatalog` — both remain the primary
  release decision.
