## 真实链路与修复

App 检查先启动原固定基础镜像，在客体 ext4 写入专用哨兵，记录已安装包和磁盘来源；停止后在同一可写磁盘升级 runner，再次停止、重开。检查实际二进制摘要、包版本、原磁盘来源、哨兵内容、并发 EXEC／PTY 的独立环境变量及 PID 1 未被污染。独立 RISC-V 检查程序也在客体内实际执行，65 项参数／输入／环境解析检查通过。

首次真实检查暴露了正常停止时丢失客体未写回数据的问题：宿主 backing file 的同步不能保存仍在客体内核内存中的脏页。生产路径现于关闭引擎前发出有界 `/bin/sync`；调用者的取消和临时凭据不会污染此操作。无法确认写回时仍安全停止，但不得报告干净保存；确认停止与保存失败分别处理，保留恢复所需磁盘并释放实际已结束实例的租约。

写回、引擎停止和磁盘捕获完成前，实例及代次继续登记，真实运行状态、内存占用和启动资源所有权可查询；新命令、PTY、服务、转发和后端重新连接受阻。失败停止的存活实例获得新的隔离代次，旧关闭回调不能删除它。现有 33 项资源调整／生命周期竞态及磁盘捕获、租约、取消和凭据隔离检查均纳入本批 50 项检查。

原始失败保留：首次客体检查的三条哨兵断言失败未改写；修复后的原断言实际通过。后一批 49/50 的唯一失败是测试把既有“停止进行中”拒绝期待成另一种错误；定向修正期待后通过，本批再完整执行 50/50。没有把局部重跑改记成原批全部通过。

## 组件生产与交付边界

生产脚本读取当前 App 的导入约束。大于普通未知归档上限的稀疏镜像，只能沿 App 已有的目录信任路径安装：镜像 ID 和完整归档 SHA-512 必须被 App 固定，声明大小、额外空间和绝对解包上限仍受检查；普通外部导入上限未放宽。

源码引用使用基础发布中实际存在且有摘要的 relink 文件，并核对编译器、静态库所属包及源版本。仅有元包名称不足以证明对应源码。新二进制重用未变化的内核、bbl 和基础用户空间，不新增科学依赖，不重新分发无变化的大型源码包。本地生产记录与 GitHub Actions 执行记录分别表示。

仍需完成新镜像身份、归档、App 目录固定、实际下载／安装／旧磁盘采用及公开组件读回；完整环境模板迁移也单独保留。此记录不证明多核新组合、实体设备性能、Mac 挂起崩溃修复或其余 CAD 验收，不替代整轮发版门槛。
