# 室内装修：成套施工图与柜体深化出图设计

日期：2026-11-12。状态：产品与技术设计，完整室内出图器未实现；独立切片已有实体、样例视图和复查，STEP 移动补丁仅在私有 CAD 副本验过，尚待主线整合，见[实际验证记录](qualification/FLOE_INTERIOR_COMPONENT_20261112.zh-CN.md)。用户明确本软件主要用于室内装修，并要求支持柜体结构图及其他工程图纸。本方案调整默认工作流与交付重点，保留[此前 19 项 QA](FLOE_BUILDING_EDITOR_REQUIREMENTS_QA_20261112.zh-CN.md)的建筑、结构、机电和独立导出目标。

## 一、以室内装修作为默认工作流

默认项目模板面向住宅及常见商业室内装修，按“量房与资料 → 现状与明确的拆改 → 室内方案 → 饰面／家具／柜体 → 图纸与清单 → 独立成果交付”组织。项目首页优先楼层、房间、资料、量尺、室内和柜体任务；完整建筑／结构／机电功能继续作为同工程内的专业工作区。

“室内自动设计沿用当前建筑平面”的 QA 17 继续有效。拆改是用户明确发起的建筑编辑任务，具有自己的现状／拆除／新建／保留分类、依据和版本，不能由一次自动家具布置隐式改变墙或门窗。

图纸由工程内容和交付目的决定。同一项目不强制生成所有类型，不要求用户逐项填满全部表格才能开始设计。没有对应系统、构造或资料的图纸可不加入该次图纸集；需要但缺信息的项目进入待补列表。

## 二、室内工程的图纸目录

已形成[机器可读目录](design/building-project/drawing-catalog-v0.json)：**7 组、41 种图纸／表格类型**，包含生成方式、必要输入和适用范围。该数量是设计目录，不代表已实现 41 个生成器，也不代表一个工程必须有 41 张图。

| 图纸组 | 主要内容 | 生成依据 |
| --- | --- | --- |
| 图纸基础与量房 | 封面、目录、修订、设计说明、图例、量房现状与尺寸、待复量／现场问题 | 项目资料、实测来源、现状构件和图纸登记 |
| 拆改与定位 | 拆除／保留、新建墙体与门洞、定位放线及尺寸 | 构件阶段、已明确的拆改决定、轴线／基准和标高 |
| 室内布置与饰面 | 家具设备、厨卫定位、地面铺装、墙面饰面、吊顶标高、天花综合定位 | 房间、资产实例、饰面区域、铺装规则、吊顶与设备 |
| 灯光、水电与机电协调 | 灯具定位、开关控制、强弱电点位、配电／回路／系统图、给排水、暖通新风、综合与检修避让 | 设备、点位、标高、专业系统关系和维护空间 |
| 立面、剖面与施工节点 | 房间各向立面、室内剖面、湿区构造、地墙顶／门套／踢脚收口、自定义节点 | 对应房间／切面、构造层、材料和人工深化内容 |
| 柜体深化与生产准备 | 安装定位、门抽外立面、内部结构立面、横纵剖面、装配爆炸、单板件、封边木纹、孔槽、五金、台面、排板、板件标签 | 柜体装配、稳定板件身份、材料、连接／五金和加工规则 |
| 明细与工程量 | 房间饰面、家具设备灯具、门窗洞口、柜体板件五金清单 | 同一工程版本的构件、资产定义和明确的统计规则 |

立面和节点还要通过平面索引、剖切／详图号与图纸位置互相定位。图号、分组、图签、比例、符号及单位按项目模板配置；不把一套任意编号当作所有地区的统一标准。

## 三、柜体需要交付哪些图

| 成果 | 图中必须表达的内容 | 所需信息 |
| --- | --- | --- |
| 安装定位与总图 | 所属房间、沿墙关系、总宽高深、安装标高、收口／填板和现场接口 | 实测／采用尺寸、基准、柜体及相邻环境 |
| 外立面与门抽图 | 柜列、门板／抽面分配、缝隙、把手与开向、表面材质和主要尺寸 | 门抽配置、饰面、尺寸约束与活动方向 |
| 内部结构立面 | 层板、竖隔板、挂衣／收纳区、抽屉箱体、背板及内部净空 | 真实柜体装配和部件关系 |
| 横纵剖面 | 进深、板厚、背板槽、层板／门板相对位置、台面／踢脚及连接节点 | 板件局部坐标和选定构造；不是仅对外包盒切一刀 |
| 装配与爆炸图 | 板件和五金编号、装配位置、引线、必要的顺序／连接说明 | 稳定部件身份及装配定义，对应同一 BOM |
| 单板件下料尺寸图 | 成品与毛坯／下料尺寸、厚度、数量、局部原点、参考边和正反面 | 构造、加工余量与板件规则；两类尺寸不能混用 |
| 封边、饰面与木纹图 | 每条边的封边类型／厚度、暴露面、正反饰面、纹理方向／对纹关系 | 明确的边／面身份、材料与封边规则 |
| 孔位、槽口与连接图 | 加工面、孔径／深度、坐标基准、槽与连接件、通孔／盲孔等实际定义 | 已选连接／五金规则及版本；缺失时标为待确定，不生成假孔位 |
| 五金安装与避让图 | 厂商产品／配置、安装位置、开合包络、相邻门抽／墙／设备干涉 | 对应五金定义、尺寸适用范围和运动规则 |
| 台面、填板与设备开孔图 | 台面拼接、边型、挡水／收口、设备开孔与接口 | 几何、设备模板、材料及安装条件 |
| 排板裁切图 | 原板规格、板件排列、切割顺序或路径类别、木纹限制、锯缝和余料 | 下料尺寸、库存／原板与选定裁切规则 |
| 板件标签与清单 | 可追溯的柜／板编号、规格、材料、封边、数量和装配归属 | 与各视图和 BOM 一致的版本及身份 |

### 本次补充：组合图、柜体斜视与正式尺寸

用户进一步明确要求组合图、柜体斜视图，以及正式交付时的柜体深度、高度等尺寸标注。这些均属于目标成果，不以当前三张几何样图代替。QA 20–22 已确认全部预研方向继续推进，不设产品优先级；此前已经确认的柜体设计、生产准备及关联更新范围继续保留。

组合图采用已确认的“整组安装总图＋单柜深化图”：每柜正／侧／顶／剖／斜视组合页，并配装配／爆炸图和编号明细。可配置的柜体斜视用于表达空间、部件和装配关系，并与正投影、剖面及编号明细对应。具体纸张和版式继续作为模板深化，不能把外观截图作为已完成工程斜视图的证据。

正式尺寸需明确总宽、总高、柜身深度及包含门面／饰面的总深度，避免把不同尺寸基础混用。分格净空、板厚、安装定位及加工尺寸按适用图种继续深化；加工尺寸仍须有明确的材料、封边及五金依据。按已确认的 QA 22，尺寸自动生成并允许人工调整，按图种分层显示；模型修改后更新关联数值，保留人工补充与排版。

当前独立组件只验证柜内立面、侧剖和顶板轮廓。完整组合图、柜体斜视和正式尺寸标注均尚未验收。

一个普通装饰网格可以生成外观投影和布置符号；只有具备实际板件、装配和加工数据的柜体，才能生成相应深化结果。导入家具或 AI 生成模型时，表示类型和可编辑程度继续按[资源与转换蓝图](FLOE_BUILDING_EDITOR_CORE_REUSE_AND_DATA_BLUEPRINT_20261112.zh-CN.md)记录。

加工文件按具体机器／加工系统另做适配与验证。本轮没有确认某一种 CNC 方言，也不将一份板件 DXF 自动称为可直接加工的机床程序。

## 四、图纸怎样从同一工程派生

沿用现有原生 CAD 图纸存储和二维编辑器。项目资料数据库登记来源、条件、问题和任务；图纸中的视图、原生几何、标注和页面仍由原生文档负责，不在 SQLite 维护另一份可分叉的图纸模型。

每个视图至少保存：

- 稳定视图身份、图纸类型、楼层／房间／柜体／板件选择范围和阶段过滤。
- 投影／反射平面／切面、裁剪、显示精度、可见类别及适用比例。
- 原生构件、体／面、柜体部件或系统对象的对应；依赖的模型、资料、资产、材料和五金版本。
- 与模型关联的尺寸、标高、标签、索引和明细；人工绘制的节点、说明及局部排版独立保留。
- 当前／需更新／需修复／缺少输入等状态，以及上一次成功生成的来源指纹。

每张图纸保存自己的纸张、比例、图框／图签、页面内容、图号和修订；图纸集保存有序目录、模板与导出范围。图纸和视图不是一一对应，一页可放平面、立面和详图，多页也可引用同一视图定义。

设备／家具优先使用库中匹配的二维符号，并与三维实例的实际尺寸、朝向和标高保持关系。图纸的线型、填充、符号和尺寸单位是工程表达；不靠家具高精度外观网格自动推导全部施工信息。

## 五、修改、联动和来源追溯

例如一个柜体从 2400 mm 改为 2600 mm：

1. 验证房间安装条件、柜型允许参数及明确的板件构造，通过同一原生模型操作修改。
2. 在构造规则规定顶底板夹于两块 18 mm 侧板之间的示例中，顶底板相应长度从 2364 变为 2564 mm；其他构造使用其自己的规则，不能套用这条示例公式。
3. 对应外立面、内部立面、剖面、尺寸线、板件表、封边／算量及排板标记为需更新，稳定部件编号保持可追溯。
4. 五金与孔位根据它们的适用条件和安装基准重新校核；尚未绑定的规则继续显示待补，不靠比例缩放旧孔位。
5. 更新派生视图时保留人工说明和详图。失去对象对应的标注显示待修复，并提供定位／重连入口，不无声删除或继续显示旧数值。
6. 视图中可定位构件及采用依据；资料库也能查到该尺寸来源和相关图纸。

图纸的显示状态、工程量、板件表和导出都绑定输入版本。项目重开、对象改名、补扫、素材库更新和换助手后，这些关系仍要存在。普通操作沿用现有任务授权和撤销规则，不为每张图重复增加确认。

## 七、已有代码与具体缺口

本轮读取 [CADDrawing.swift](../FloeAgent/ThirdParty/FloeCADKit/Sources/FloeCAD/Floe/CADDrawing.swift)，已有 front／top／side／iso／section／detail／exploded 视图类型、多视图页、比例、对齐、源几何／放置指纹和模型版本关联。它是可复用基础，不代表室内全部图纸类型已实现。

[CADDrawingManufacturing.swift](../FloeAgent/ThirdParty/FloeCADKit/Sources/FloeCAD/Floe/CADDrawingManufacturing.swift)已有制造标注的结构化表达；柜体板件、封边、木纹、选定五金和施工节点仍需对应的领域输入与模板，不能把机械制造标注界面原样当作柜体深化流程。

当前 [CADDrawingService](../FloeAgent/ThirdParty/FloeCADKit/Sources/FloeCAD/Floe/CADDrawingService.swift) 明确限制每页最多 12 个源体。整层和多板件柜体需要分组／范围查询、增量投影、按任务预算和大规模视图处理方案。保留现有预算保护，不能简单解除上限后宣称整工程出图完成。

本轮没有改动或构建上述源码。新增图纸目录不影响先前数据库原型的 24 项检查；该原型没有验证这些出图行为。

## 八、实施验收场景

- 一个多房间装修工程从量房现状、拆改、家具／饰面、天花灯光、水电点位，组织成一致的图纸集；缺数据处能定位到待补项。
- 一面包含门窗、壁龛、踢脚和饰面的墙，在平面／立面／剖面及对应标注中更新，并保持人工节点内容。
- 同一柜体生成上述适用的深化图、板件／五金表和标签；每个编号可回到原生部件。调整宽度、板厚和门抽配置后，关联结果更新。
- 普通网格家具仍能用于方案布置；缺少板件／五金规则时，相应制造图明确保留待补状态。
- 对象删除、拓扑变化或补扫后，失去对应的尺寸与索引可见且可修复；已导出独立副本保持独立。
- 超过当前 12 源体预算的柜体与整层模型，在新实现中有实际性能、取消与恢复证据，不靠截断模型或丢部件通过。
- 批量 PDF／DWG／DXF 使用同一固定输入版本，图纸目录、比例、文字、线型、图层、图签和清单读回一致；部分失败保留成功成果并显示真实状态。
- 图纸保存重开、工程搬移及依赖打包后，原件、视图、标注和资料来源仍可定位。交付采用明确修订快照，后续编辑不改写既有文件。

验收按各图纸实际数据、生成与读回行为记录，不把图纸排版完成等同于专业设计或制造验证。地区规则继续按 QA 12 记录来源、版本和覆盖范围。
