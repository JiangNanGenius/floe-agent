# Skill dependency and package author contract

## macOS original packages and version identity

The same-Mac bridge uses a separate signed `macos/catalog.json` and `macos/catalog.json.sig` feed. Its initial schema is `schemaVersion: 1`, `channel: "macos-original"`. It does not change the iOS/Android curated schema or claim RISC-V/guest qualification. The existing production signing identity signs exact feed bytes; no new client trust key is introduced.

Each entry declares `id`, bilingual `name`/`description` (`en`, `zh-Hans`), existing category, semantic `version`, `minimumAppVersion`, upstream `repository` (`owner/repo`), `subdirectory` (empty for root), immutable 40-hex `commit`, `license`, package-relative `licensePath`, `digest`, and `files`. Each file declares package-relative `path`, repository-relative `sourcePath`, exact `sha256`, byte count `bytes`, and Git `mode` (`100644` or `100755`). Include `SKILL.md` and the declared license file. No path traversal, absolute paths, symlink entries or install commands are allowed. The whole original package retains the existing small-package size policy (16 MiB here); dependencies are not bundled into Skills.

`digest` is SHA-256 of UTF-8 JSON of the files sorted by `path`, with each object containing only `path`, `sourcePath`, `sha256`, `mode`; use sorted object keys, compact separators and unescaped Unicode/slashes. `sourcePath` normally equals `subdirectory/path`; the declared license file may instead point to the repository's root license and be copied without changing its bytes. Every file is fetched from the declared upstream commit and installed byte-for-byte with its declared mode. No compatibility test or Linux adaptation is required to offer the original. Content authenticity and safe installation are still checked.

A published `(id, version)` is immutable across commit, manifest and modes. A changed upstream commit or files requires a new version even when an upstream project reuses a tag. `minimumAppVersion` gates older clients. The first capable App version must be filled from the release owner's verified build; source alone is not evidence of availability. Mac installation receipts identify the original target, source commit, publication commit and file manifest digest, and intentionally omit Linux archive/review/qualification claims.

The companion installs into immutable version directories and atomically updates its active index. Running/checkpointed tasks pin versions by owner and retain them across restarts; updates do not repoint those tasks. Removing an installed Skill removes its active index entry; versions still referenced by a task remain until safely unpinned. Existing iOS/Android and Mac installations may share an upstream Skill ID without sharing files, dependencies, enable state or execution receipts.

Mac dependencies execute in the real host task environment through the existing shell and permissions. Do not apply Debian/riscv64 dependency plans to macOS or uninstall external system/Homebrew packages during cleanup. Existing local dependency schema and version semantics remain unchanged; original external Skills can continue to let the model prepare their dependencies.

Author validation: `FloeMacBridge/scripts/validate_original_catalog.py` checks schema, source identity, package paths, version fields, file/mode digests and size bounds. It does not execute or qualify a Skill. The store publisher must sign and publish the Mac feed before clients can offer real original downloads; a missing feed must remain visibly unavailable.
