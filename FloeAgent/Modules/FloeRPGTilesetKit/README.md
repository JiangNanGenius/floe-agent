# FloeRPGTilesetKit — real RPG Maker atlas rendering for the auxiliary map editor

Status: **independent source component with a complete implementation package;
its native host tests, iOS object compile and iPad touch acceptance remain the
App integration owner's responsibility.**

The existing structural RPG map editor drew colored GIDs. This package replaces
that presentation with real, engine-resolved tileset atlases and a visual tile
palette while keeping the existing `GameEditingSession`, engine adapters,
revision/CAS, undo/history and save/reopen services.

## What is implemented

- Tileset record resolution for XP (`Data/Tilesets.rxdata`, `Graphics/Tilesets`,
  seven `Graphics/Autotiles` images), VX (`.rvdata`), VX Ace (`.rvdata2`) and
  MV/MZ (`data/Tilesets.json`, `img/tilesets`) with deterministic,
  case-insensitive project-file resolution.
- Real tile-id ranges for XP and VX/Ace/MV/MZ (A1..A5, B..E; 48-shape
  autotiles), source geometry for ordinary cells and four-quarter autotile
  layouts, official MIT quarter tables, and stable-frame handling for animated
  A1/XP sheets.
- A bounded ImageIO decode cache (encoded/pixel/decoded-byte limits, LRU,
  generation fencing) and a render planner that resolves only the visible map
  cells. Images are never borrowed from another project or RTP.
- Multi-layer composition honoring per-layer visibility, source alpha, event
  markers and optional static event character images using the real page
  image/index/direction/pattern fields.
- A native SwiftUI editor: real visual palette (A1..A5, B..E; XP autotiles and
  tiles), shape-variant sheet in opened details, paint/erase/fill/select/object,
  zoom, layer panel, selection fill, event/object editing and missing-asset
  diagnostics. Internal GIDs appear only in the opened detail sheet.
- English/Simplified Chinese copy, 44 pt targets, actionable missing-asset
  messages with no automatic RTP download.

## What is deliberately not claimed

- No RTP/Enterbrain art or scripts are bundled. Fixtures are generated by
  `Tools/generate_fixtures.py` and `Tools/generate_binary_data.rb`.
- Encrypted RGSS archives, encrypted MV/MZ images and proprietary engines are
  not decoded.
- VX/Ace A1 animation is shown at a stable representative frame (metadata
  reports the limitation); XP autotile animation is stable frame 0. MV/MZ A1
  water/waterfall supports the documented animation frame selection.
- MV/MZ shadow/region channels are preserved but not rendered; they are not
  tile layers and the scene shader is engine-owned.
- Event character images are static page-0 previews; no movement animation.
- Full gameplay/RGSS execution is outside this component.

## Integration contract (App host)

The component does not edit `project.yml`, the root `Package.swift`, the App
target or Git. The App host should:

1. Copy/register `FloeRPGTilesetKit` (and the optional UI target) as an
   independent module; keep the declared dependency direction
   `FloeRPGTilesetUI -> FloeRPGTilesetKit -> FloeRPGProjectKit ->
   FloeGameEditingKit -> FloeGameKit`.
2. At the RPG workspace/editor host, pass the already-resolved `RPGEngine` and
   supply the optional factory to the existing editor shell:

```swift
GameEditingSessionView(
    session: session,
    onClose: onClose,
    tileMapEditorFactory: { session, path in
        AnyView(RPGTileMapEditorView(session: session, path: path, engine: rpgEngine))
    })
```

The private vendored `GameEditingSessionView` copy already supports this
optional factory; the changed vendor files (factory and event deletion) are
recorded in `VENDORED.md`.
The generic color-GID editor remains the fallback for non-RPG maps.

## Verification commands (host, once the native window is granted)

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
cd FloeAgent/Modules/FloeRPGTilesetKit
swift test -j 6
swift run floe-rpg-tileset-render --fixtures Tests/FloeRPGTilesetKitTests/Fixtures --out /tmp/floe-rpg-tileset-renders
swift build -j 6 --target FloeRPGTilesetUI --triple arm64-apple-ios26.0
```

All native checks must run through
a host resource guard when the shared
window is available; do not nest wrappers. The Swift 6 UI/SIL object check
must use actual iOS objects, not `-typecheck`.
