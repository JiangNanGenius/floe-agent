# USBDriverKit code handoff

This is code-level predevelopment, not an installed driver bundle. DriverKit service, user client, wire validator and real control/bulk backend have been object-compiled with actual SDK iig output. No signing identity, entitlement grant, App target or system activation has been changed.

- Compile `FloeUSBSerialDriver.iig` and `FloeUSBSerialUserClient.iig` with iig, then compile both generated implementation files, `FloeUSBSerialDriver.cpp`, `USBSerialBackend.cpp` and the shared C wire source. Retain generated class metadata; compiling only the handwritten C++ is insufficient.
- Match **explicit authorized** vendor/product/interface combinations on `IOUSBHostInterface`; the service's `IOUserClass` is `FloeUSBSerialDriver`. This is also verified by the App IOKit channel before opening the user-selected registry entry. Never substitute another project's USB entitlement or use a wildcard to claim hardware access.
- `NewUserClient` calls `Create(this,"FloeUSBUserClientProperties",...)`. The service personality must supply that nested dictionary with kernel proxy `IOClass = IOUserUserClient` and `IOUserClass = FloeUSBSerialUserClient`. Service class/proxy, bundle/server identifiers, current SDK build settings and team-granted USB match entries must be configured together in the real target. Missing properties are an error, not a fallback path.
- App opens user-client type0; ExternalMethod selector0 accepts a bounded versioned struct only (no scalar/descriptor/async completion variants). INFO supplies generation/device info; subsequent requests must match it and strictly increasing request IDs. One client exclusively claims the interface. USB stop/detach fences subsequent transfers.
- DriverKit deployment target **27.0** was used with SDK27.2. Earlier deployment targets were not qualified. This is separate from the Swift host's iOS26 compile. Host/driver minimum OS and actual distribution profiles must agree before embedding.
- iPadOS uses the App's Communicates With Drivers entitlement and system Settings approval; it does not use macOS SystemExtensions activation. Disabled/missing drivers remain unavailable. Common-chip candidates and failure paths are not hardware compatibility results.

Follow the [Apple client example](https://developer.apple.com/documentation/driverkit/communicating-between-a-driverkit-extension-and-a-client-app), [entitlement request process](https://developer.apple.com/documentation/driverkit/requesting-entitlements-for-driverkit-development) and [iPad distribution guidance](https://developer.apple.com/videos/play/wwdc2022/110373/), plus the project's [USB research](../../../../docs/FLOE_USB_SERIAL_REUSE_RESEARCH.zh-CN.md). This handoff grants no account permissions or approval to alter App signing. No background audio workaround or downloadable executable driver is included.
