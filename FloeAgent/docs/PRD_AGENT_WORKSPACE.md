## 1. 产品目标与原则

### 1.1 产品目标

1. **Chat-first**：打开 App 即可输入，对话是产品的主界面与主路径，而非功能入口集合。
2. **可用的工作空间**：项目/文件/执行环境围绕对话组织，Agent 能真实读写文件、真实执行代码。
3. **可托付的日常工具**：状态诚实、授权可控、凭证安全，成功/失败/取消都有明确收尾。

### 1.2 产品原则（验收红线）

| 原则 | 含义 | 反例（不允许） |
|---|---|---|
| Chat-first | 首屏即输入框；AI 不可用时其余功能完整可用 | 无模型时卡在引导页/无限加载 |
| 诚实状态 | 机器状态映射为人类可读本地化文案；能力未实现则明确"不可用" | 直接暴露 `preparing/endTurn`；放假数据模拟成功 |
| 不模拟 | 文件工具、JS/Python 执行、图片能力均为真实实现；做不到的打开真实界面或返回明确限制 | 模拟执行结果、占位文字、空白详情列 |
| 安全边界 | 路径逃逸防护、凭证只进 Keychain、灾难性操作保护不因任何模式削弱 | 数据库明文存密钥；完全控制模式放行 `rm -rf` |

## 2. 用户故事

### 2.1 日常用户

| 编号 | 用户故事 |
|---|---|
| US-D1 | As a 日常用户，I want 打开 App 就能直接输入问题，so that 我不需要先理解项目/模型等概念 |
| US-D2 | As a 日常用户，I want 在还没配置模型时也能浏览文件、主机和设置，so that 我可以按自己的节奏完成配置 |
| US-D3 | As a 日常用户，I want 看到 AI 的思考过程和工具执行步骤（名称/状态/耗时），so that 我知道它正在做什么、卡在哪一步 |
| US-D4 | As a 日常用户，I want 出错时看到人话提示和重试按钮，so that 我不需要看懂技术错误码 |
| US-D5 | As a 日常用户，I want Agent 要写文件前先给我看看改了什么（Diff），so that 我不会被悄悄改掉重要文件 |

### 2.2 进阶用户

| 编号 | 用户故事 |
|---|---|
| US-A1 | As a 进阶用户，I want 把项目目录加入工作空间并在对话中引用其中的文件，so that Agent 能在真实代码库上工作 |
| US-A2 | As a 进阶用户，I want 按"仅这一次/本次任务/当前项目/主机"粒度授予权限，so that 我在效率与安全间自主权衡 |
| US-A3 | As a 进阶用户，I want 在 SSH 主机上远程运行 Python、在本机跑 JS 脚本，so that 轻量自动化不需要离开 App |
| US-A4 | As a 进阶用户，I want 在 iPad 上边看对话边开文件检查器，so that 我能对照代码审查 Agent 的修改 |
| US-A5 | As a 进阶用户，I want 设置里每一项都是真实可调且重启后保留的，so that 我可以信任配置状态 |
