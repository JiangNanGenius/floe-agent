# Video acceleration source layout

This directory is the guest userspace client. The complete source is split so
the host and guest can be built and owned separately:

| Path | Role |
| --- | --- |
| `FloeAgent/Modules/FloeLinuxVideo` | macOS/iOS host package: VideoToolbox/CoreMedia/CoreVideo ABI1 implementation, ImageIO JPEG fallback and the additive typed broker |
| `FloeAgent/LinuxGuest/virtio-media` | guest kernel module, ABI probe/inputs, module build and boot-overlay installer |
| `FloeAgent/LinuxGuest/acceleration/video` (this directory) | `floe-codec` V4L2 CLI and broker client |
| `FloeAgent/ThirdParty/ARM64EMU` | ABI4 virtio-media device, broker wiring and engine lifecycle (scoped source patch) |

## Guest image install

1. Build the guest kernel module against the exact image kernel using
   `LinuxGuest/virtio-media/scripts/build_module.py`; retain the module
   `vermagic`, compiler receipt and SHA-256.
2. Install `virtio-media.ko` and its module dependency files through
   `LinuxGuest/virtio-media/boot_overlay/install_recipe.py` (or
   `image_gate.py` for a read-only preflight). The overlay must include the
   module in the rebuilt initrd and must not mutate a frozen image.
3. Build the client with `make CC=<aarch64-linux-musl-gcc>` in this directory
   and install `floe-codec` as `/usr/local/bin/floe-codec`.
4. The App/engine must create the machine with ABI4 video enabled and both
   nodes (decoder slot 28, encoder slot 29). A machine without a video-enabled
   image keeps the historical no-video layout.

## Host package

`FloeAgent/Modules/FloeLinuxVideo` is a local SwiftPM package with
`FloeLinuxVideoNative`, `FloeLinuxVideoHost` and `FloeLinuxVideoBroker`
products. It uses only public VideoToolbox/CoreMedia/CoreVideo/ImageIO APIs.
The frozen ABI1 header is unchanged; the broker is additive and does not
extend ABI1. `FLVProbeSamples.m` contains synthetic one-frame probe samples
generated by the package tests; it is not user content.

## Capability truth

- A codec/direction is hardware only after a real hardware-required session
  probe; software sessions are counted separately and never as hardware.
- The V4L2 nodes expose standard `QUERYCAP`; broker discovery uses the
  `bus_info` token and a loopback-only connection. No host path, NAT rule or
  new entitlement is added.
- The current `v8` image has no video node and must not declare video.
  `openGL`/`openCL`/video capabilities remain unavailable until the installed
  image is qualified with the exact artifacts.
- Compile/link, module load, FFmpeg/V4L2 traffic, hardware-vs-software counters,
  pixels and App acceptance are separate gates. Source presence is not proof.
