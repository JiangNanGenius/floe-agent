# `produce-update-delta.py` — release-side APK delta producer

SPDX-License-Identifier: MPL-2.0

This is a **host-only release tool**, not part of the Android build. It reads
two exact signed Full APKs (the previous public base and the new public target),
verifies their identity with the pinned Android SDK tools, writes one FloePatch
v1 binary and one JSON manifest, and proves the patch by reconstructing the
target from the base and comparing the exact SHA-256.

The App (`app/src/full/kotlin/com/floe/android/host/update/`) can then offer a
much smaller download. It never trusts the patch by itself:

* the manifest and the patch must both be listed in the release's own
  `SHA256SUMS` (the existing release-integrity chain);
* the manifest's target hash must equal the release's full-APK checksum entry;
* the installed base APK's exact SHA-256, size, versionName/versionCode,
  package and signer set must match the manifest before one byte is applied;
* the reconstructed file must match the target size and SHA-256, then pass the
  same package/version/signer/ABI/minSdk admission as a full APK before the
  system installer is invoked;
* any wrong base, unbound manifest/patch, truncation, corruption, oversized
  patch, disk shortfall or invalid output deletes the generated bytes and
  offers the full APK instead. A non-beneficial patch is not produced at all.

## Usage

```sh
export ANDROID_SDK_ROOT=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk

python3 scripts/update/produce-update-delta.py \
  --base-apk   /path/Floe-Android-<base>-full-arm64-v8a.apk \
  --target-apk /path/Floe-Android-<target>-full-arm64-v8a.apk \
  --base-version-name   <base>   --base-version-code   <base-code> \
  --target-version-name <target> --target-version-code <target-code> \
  --release-tag android/v<target> \
  --sums /path/to/that-release/SHA256SUMS \   # APK (+ source) entries already present
  --out-dir /path/out
```

Outputs:

| file | purpose |
| --- | --- |
| `Floe-Android-<target>-from-<base>.delta` | the FloePatch v1 patch |
| `update-delta-v1.json` | release manifest (bounded, strict) |
| `SHA256SUMS.entries` | exactly two lines to append to the release `SHA256SUMS` |
| `PRODUCER_REPORT.json` | measured sizes/ratio, op stats, round-trip proof, tool paths |

`--sums` is **required for a release**: pass the SHA256SUMS that already carries
the target APK line (the release process generates it from the exact assets),
then append `SHA256SUMS.entries` for the manifest and patch and publish the
four-line file. It may be omitted only for a local measurement, where the
producer still hashes both APKs and its round-trip proof remains authoritative.

Exit codes: `0` patch verified and beneficial, `1` input/tool failure,
`2` usage, `3` verified but **not beneficial** (only the report is written,
unless `--allow-not-beneficial`).

`--check` verifies identities and the SHA256SUMS binding without writing
anything. Running the producer twice on the same inputs is byte-identical (no
timestamps or absolute paths enter the patch/manifest).

## Publication contract (release owner)

1. Upload the `.delta` patch and `update-delta-v1.json` **in addition to** the
   unchanged full APK, corresponding source and `SHA256SUMS`.
2. Append `SHA256SUMS.entries` to `SHA256SUMS` (both new lines) and re-read the
   release; the App requires both entries.
3. The delta is only usable by an installed build that already contains the
   delta client **and** whose exact APK equals `--base-apk`. The first release
   that carries this client cannot itself arrive as a delta: old clients have
   no delta code, so the bootstrap install is a full APK.
4. Do not attach a delta to an already published/immutable tag. Generate the
   patch from the exact prior public APK and the exact new signed target at the
   time of that new release.

## Format (FloePatch v1)

```
magic          11 B   "FLOEPATCH1\n"
header length   u32 LE
header          UTF-8 JSON: format/formatVersion, base{sha256,sizeBytes},
                target{sha256,sizeBytes}, ops{copies,copyBytes,inserts,insertBytes},
                matcher{name,window,stride}, producer
ops (streamed):
  0x01 COPY     u64 LE baseOffset, u32 LE length
  0x02 INSERT   u32 LE length, <length raw bytes>
  0x00 END      u64 LE total written
```

The App applies it with one reusable 1 MiB buffer, a read-only base file and a
private staging output; the final SHA-256 is computed while writing. The
producer's `apply_patch` is the reference implementation used for the
round-trip proof and is covered by `test_produce_update_delta.py`.

## Measured example (Alpha16 → Alpha17, 2026-10-30)

```
base   444,671,339 B  404d9da5…1271e4
target 445,796,721 B  b0c9daf4…4e05f
patch  143,477,820 B  de2fb7af…fc1e66  (32.2% of the full APK, 70% saved)
round-trip SHA-256 == target SHA-256
```

This measurement is evidence for the pipeline only; it is **not** a published
Alpha17 asset (the Alpha17 release and its three assets are immutable, and no
installed client can consume a delta yet).
