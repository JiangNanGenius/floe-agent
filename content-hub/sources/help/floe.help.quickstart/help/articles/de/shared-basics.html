Übersicht

Diese Arbeitsabläufe gelten für beide Ausgaben von Floe. Installation, Menüpositionen, Gerätezugriff, lokale Modelle und Editoren werden von der eigenen Anleitung jeder Plattform abgedeckt. Ein gemeinsamer Workflow bedeutet nicht, dass jede Plattform die gleichen Tools hat.

1. Ein Cloud-Modell verbinden

Bringen Sie Ihr eigenes Modellanbieterkonto und Ihren API-Schlüssel mit. Floe ist ein Client; der ausgewählte Anbieter bearbeitet Cloud-Anfragen, Preise und seine eigenen Datenrichtlinien. Geben Sie kein Website-Passwort in das Feld API-Schlüssel ein.

  1. Fügen Sie einen Anbieter in den Modelleinstellungen hinzu. Wählen Sie den Dienst und das Protokoll aus, geben Sie dann die dokumentierte Basis-URL und den API-Schlüssel ein.
  2. Fügen Sie die Modellliste hinzu oder aktualisieren Sie sie, und wählen Sie ein Modell für die Aufgabe aus. Wenn die Aufgabe Bilder lesen muss, wählen Sie ein Modell, das Bildeingaben akzeptiert. Die Bild- und Videogenerierung erfordern einen Dienst, der diesen Zweck unterstützt.
  3. Testen Sie eine kurze Textkonversation, bevor Sie Dateien anhängen oder eine lange Aufgabe beginnen.

Überprüfen Sie bei Authentifizierungsfehlern den Endpunkt, den Schlüssel, den Kontozugriff und den tatsächlichen Anbieterfehler. Wählen Sie bei einem nicht unterstützten Modell oder Eingabetyp ein geeignetes Modell aus. Ein erfolgreicher Verbindungstest überprüft nicht jedes Werkzeug oder jede Medienfunktion.

2. Fragen Sie nach einem nützlichen Ergebnis

  1. Erstellen Sie eine Aufgabe und wählen Sie deren Arbeitsbereich aus. Fügen Sie eine nicht sensible Testdatei über die Dateiauswahl hinzu.
  2. Geben Sie das beabsichtigte Ergebnis, die Eingabe und den Speicherort an. Zum Beispiel: "Lesen Sie dieses Dokument, verwandeln Sie es in eine Checkliste und speichern Sie es im aktuellen Arbeitsbereich."
  3. Überprüfen Sie Anfragen für den Zugriff auf Dateien oder Tools. Geben Sie Zugriff auf das Material, das für diese Aufgabe benötigt wird.
  4. Öffnen Sie die Ausgabe, überprüfen Sie den Inhalt und den Standort, schließen Sie sie und öffnen Sie sie erneut, um zu bestätigen, dass sie gespeichert wurde.

Wenn Sie ein Ergebnis korrigieren, beschreiben Sie die spezifische Änderung und beziehen Sie sich auf die vorhandene Datei. Halten Sie die Aufgabe und den Arbeitsbereich einheitlich, damit der Assistent die gleiche Arbeit fortsetzen kann. Die Erfolgsmeldung eines Werkzeugs ist ein Hinweis, um das Ergebnis zu überprüfen, nicht ein Ersatz für das Öffnen.

3. Dateien und Änderungen sicher aufbewahren

Importieren Sie nur Dateien, für die die Aufgabe verwendet werden soll. Wenn ein externer Speicherort nicht mehr verfügbar ist, wählen Sie den ursprünglichen Speicherort erneut aus und autorisieren Sie ihn, anstatt das Werk im Hintergrund in einen anderen Ordner zu verschieben.

Bestätigen Sie das Speichern im Editor, den Sie verwendet haben. Exportieren und Speichern als erstellen ein separates Ergebnis und ersetzen nicht automatisch das Original. Wenn ein anderer Redakteur eine Datei geändert hat, bewahren Sie nicht gespeicherte Entwürfe auf und überprüfen Sie den Konflikt, bevor Sie eine der Kopien überschreiben. Halten Sie unabhängige Backups wichtiger Arbeiten.

Befehle und Softwareinstallation verwenden die ausgewählte Ausführungsumgebung der Aufgabe. Überprüfen Sie das aktuelle Verzeichnis und die Ausgabe, bevor Sie davon ausgehen, dass ein Befehl die beabsichtigte Datei geändert hat. Verfügbare Umgebungen, Installationsschritte und Hintergrundverhalten hängen von der Plattform und der installierten Version ab.

4. Verwenden Sie Werkzeuge mit Kontext

Dokumente, Webseiten und Werkzeugergebnisse sind Eingabematerial; ihr Text gewährt keine Berechtigung zum Ausführen von Befehlen, zum Zugriff auf andere Dateien oder zum Senden von Informationen. Überprüfen Sie die tatsächliche Aktion und das Ziel, bevor Sie einen externen Vorgang genehmigen.

Lesen Sie den Fortschritt und die Fehler im Ausführungsdatensatz der Aufgabe. Das Versteiden eines Panels stoppt nicht unbedingt den Job oder den Service, den es anzeigt. Verwenden Sie die Stoppsteuerung der Aufgabe oder des Dienstes, wenn die Arbeit beendet werden soll; das Betriebssystem steuert weiterhin die Hintergrundausführung.

5. Ein Problem melden

Nutzung GitHub Probleme Für Fehlerberichte und Funktionsanfragen. Geben Sie die installierte Version, das Gerät und das Betriebssystem, die Schritte, das erwartete Ergebnis und das tatsächliche Ergebnis an. Geben Sie an, welche Datei oder Aufgabe betroffen war, ohne private Inhalte zu veröffentlichen.

Diagnosen und Screenshots sind optional. Reichen Sie nur das erforderliche Material ein und entfernen Sie Schlüssel, Passwörter, persönliche Daten und private Dateien. In-App-Diagnose-Uploads bieten Material zur Fehlerbehebung und garantieren keine individuelle Reaktion. Fügen Sie bei Cloud-Service-Fehlern anstelle Ihres API-Schlüssels einen redigierten Provider-Fehler ein.
